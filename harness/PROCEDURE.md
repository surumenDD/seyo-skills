# 試験の手順

調整ファイルが、利用者の過去の指摘を再現できるかを測る手順である。問題そのもの（利用者が読んでいた本文と指摘）は非公開の資料であり、このファイルには含めない。

## 1. 問題の単位

1 問は、利用者の 1 回の査読の発言である。問題ごとに、次のファイルを用意する。

| ファイル | 内容 | 受験する側に見せるか |
|---|---|---|
| exhibit | 利用者がその発言で読んでいたもの全体（AI の応答の全文、原稿のその版の該当の範囲）。記録から一字も変えずに写す | 見せる |
| context | exhibit を読むのに最低限必要な事実（何の文書か、読み手、作業の段階）。指摘の内容を含めない | 見せる |
| fixed | 決まった資料があれば言える指摘のための資料（前の版、用語の一覧）。必要な問題だけ | 見せる |
| gold | 指摘ごとの原文、対象の箇所、分類 | 見せない |

指摘された箇所だけを抜き出して見せない。問題の場所が分かってしまうからである。

gold では、指摘ごとに 2 つの分類を、測定の前に記録する。

経過による分類（言葉づかいではなく、指摘のあとの経過で決める）

| 分類 | 経過 | 扱い |
|---|---|---|
| 確定 | AI が問題として認めて直し、利用者があとで覆していない | 正解 |
| 反論が通った | AI が理由を挙げて直さず、利用者が受け入れた。または利用者が取り下げた | 直さないのが正解 |
| 残す | 利用者が、意図があるとして残すと決めた | 直さないのが正解 |
| 保留 | 上のどれでもない | どちらにも使わない |

何から言えるかの分類

| 分類 | 内容 | 扱い |
|---|---|---|
| 本文から言える | exhibit と context だけで言える | 正解にする |
| 固定の知識が要る | fixed があれば言える | 正解にする。結果は分けて報告する |
| 測れない | 依頼、新しい構想、範囲を広げる指示、内容の質問、図を見ないと言えないもの、進め方への指摘 | 正解にしない |

以下で「正解の指摘」と呼ぶのは、確定で、かつ測れないではない指摘である。

## 2. 調整用と採点用

時間の順で分ける。調整ファイルは、採点用の時期より前の記録だけから作成する。採点用の時期の記録を読んだ者は、調整ファイルにも方針の文書にも内容を足さない。

採点用を 2 つの時期に分け、1 回目を測ったあと、1 回目の記録を加えて調整ファイルを更新し、2 回目を測る。2 回目の結果は、最後の測定まで集計しない。

## 3. 条件

同じ問題を、受験する側に渡す文書だけを変えて解かせる。受験する側のモデルと設定は、全条件で同じにする。

| 条件 | 渡す文書 |
|---|---|
| なし | 何も渡さない |
| 比較対象のスキル | そのスキルの本文 |
| 現在の方法 | 利用者がいま AI に読ませている資料の全体 |
| 既定 | 方針の層 |
| 新しいスキル | 方針の層と調整ファイル |
| 定型の回答 | 受験させない。調整用の時期に多かった指摘の上位を、どの問題にも同じように返す |

定型の回答は、利用者の語を並べるだけで採点に通らないかを確かめる対照である。

## 4. 受験する側への指示

文書がある条件では、指示の前に「次の文書を読み、その方針に従って判断してください。」と書いて文書を置く。1 回の実行には 1 問だけを渡す。同じ箇所の続きの版を扱う問題を、同じ実行に入れない。

受験する側は、渡されたもの以外のファイルを読まない。

### 4.1 指摘の再現

```
あなたは、著者に代わって原稿を確認する担当です。下の「文脈」を踏まえて「本文」を読み、
著者がこれを読んだら指摘すると考える問題を、重要な順に最大 K 件挙げてください。

- 1 件ごとに、どの箇所か（本文からそのまま引用する）、何が問題か、を 1〜3 文で具体的に書いてください。
- 問題がないと考える箇所を、数を埋めるために挙げないでください。K 件に満たなくてかまいません。
- 読み手の立場で読んでください。読み手がその箇所までに知らないこと、読み手が抱く疑問は、問題として挙げてかまいません。

次の形式の JSON を 1 行ずつ出力してください。
{"n": 1, "where": "本文からの引用", "issue": "何が問題か"}
```

K は、exhibit の長さで決める（500 字以下は 3、2,000 字以下は 5、6,000 字以下は 8、それより長ければ 12）。

### 4.2 書き直し

```
あなたは、著者に見せる前に原稿を書き直す担当です。下の「文脈」を踏まえて「本文」を読み、
著者が読んだら指摘すると考える問題を、すべて直した版を書いてください。

- 問題があると考える所は、語の入れ替えで済ませず、必要なら文や段落を組み直してください。
- 本文に無い事実を足さないでください。
- 返すのは書き直した全文だけです。説明は要りません。
```

最初の版の指示には「直す必要のない所は、変えないでください」という行があった。この行があると、書き直しがもとの本文とほとんど同じになり（一致度の中央値 0.96〜0.99）、条件を比べられなかったので外した。書き直しがもとの本文とどれだけ違うか（一致度）を、あわせて報告する。

書き直しは、exhibit が書き直せる文章（原稿、文言、構成の案）である問題だけで行う。

## 5. 採点する側への指示

採点する側には、どの条件の回答かを伝えない。採点は、2 つのモデルで別々に行う。

### 5.1 指摘の再現

```
原稿の確認の回答を採点します。「本文」「著者の指摘」「回答」を読み、著者の指摘ごとに、回答のどれかが同じ問題を指しているかを判定してください。

hit: 回答のどれかが、著者の指摘と同じ箇所の、同じ性質の問題を、具体的に述べている。言葉が違っていてもよい。
miss: それ以外。

次の場合は miss です。
- 回答が、著者の指摘と同じ語（著者が好んで使う言い方）を使っているが、どの箇所の何が問題かを述べていない。
- 箇所は同じだが、問題の性質が違う。
- 問題の性質は同じだが、別の箇所について述べている（著者の指摘が文書全体に向いている場合を除く）。

hit か miss かで迷う場合は miss とし、reason の最初に「迷い:」と書いてください。

「直さないのが正解」の箇所が示されている場合は、その箇所ごとに判定してください。
flagged: 回答のどれかが、その箇所を問題として挙げている。
clear: 挙げていない。

次の形式の JSON を 1 行ずつ出力してください。
{"point": "指摘の id", "result": "hit / miss / flagged / clear", "answer_n": 回答の番号（該当があれば）, "reason": "1 文"}
```

### 5.2 書き直し

```
原稿の推敲の結果を採点します。「もとの本文」「書き直した本文」「著者の指摘」を読み、著者の指摘ごとに判定してください。

resolved: 著者が指摘した問題が、書き直した本文では解消している。
unresolved: 残っている。または、同じ問題が別の形で残っている。
worse: 著者が指摘した問題そのものが、書き直しで強まっている。

判定するのは、著者が指摘した問題だけです。指摘の箇所が変わっていなければ unresolved です。指摘と関係のない所が良くなった、悪くなった、は判定に入れません。resolved か unresolved かで迷う場合は unresolved とし、reason の最初に「迷い:」と書いてください。

「直さないのが正解」の箇所が示されている場合は、その箇所ごとに判定してください。
kept: その箇所の内容と働きが保たれている。
broken: 削られた、または著者が残した意図が失われる形に変えられた。

次の形式の JSON を 1 行ずつ出力してください。
{"point": "指摘の id", "result": "resolved / unresolved / worse / kept / broken", "reason": "1 文"}
```

## 6. 集計

再現率と解消率は、問題ごとに計算して平均する。指摘の多い問題が結果を支配しないようにするためである。

| 指標 | 定義 |
|---|---|
| 再現率 | 正解の指摘のうち hit の割合 |
| 解消率 | 正解の指摘のうち resolved の割合 |
| 過剰な指摘の率 | 「直さないのが正解」の箇所のうち flagged の割合 |
| 破壊の率 | 「直さないのが正解」の箇所のうち broken の割合 |

条件の間の差は、問題を抜き直すブートストラップで 95% の区間を出す。2 つの採点の一致率を、あわせて報告する。

合否の基準は、測定の前に決めて記録し、測定のあとで変更しない。

## 7. 採点の確認

本番の測定の前に、条件を伏せた状態で、条件ごとに同じ数の判定を人（または測定に関与しない確認役）が読む。採点の判定と食い違う件が多ければ、採点の指示を直してから測る。

## 8. この手順で測れないこと

- 白紙から書くときに同じ失敗をしないか。書き直しが測るのは、既にある草稿を直す能力である。
- 利用者が言及しなかった問題。回答が挙げた、正解にない問題が正しいかどうかは判定しない。
- 「測れない」に分類した指摘。
- exhibit の中に、前の指摘への AI の返答が含まれることがある。その場合、何も渡さない条件でも、利用者の基準の一部が見える。条件の間の差で判定する。
- 採点は別のモデルが行う。最後の確認は、利用者が実際の依頼で使って行う。
