# delegate-seyo

AI エージェントがサブエージェントや別のエージェントに作業を委譲するときの、指示書の書き方と、返ってきた結果の確認の手順を定めたスキルです。このファイルは人が読むための説明で、エージェントが読むのは `SKILL.md` です。

## 確認の状況（2026-11-16）

- 指示書と報告の文章をどう書くかという方針は、論述の層（ronjutsu-seyo）と文体の層（buntai-seyo）にあり、このスキルはそれを参照します。方針を層に分けたときも、手順、検査の方法、スクリプトは変えていません。
- `references/brief.md` の例（ライブラリの認証の調査、報告書の数値の確認）は説明のために作成した例で、実際にあった依頼ではありません。
- 方針を層に分けたあとの版では、まだ委譲を行っていません。

## 何のためのスキルか

エージェントに作業を委譲すると、次のようなことが起きます。

- 「確認して」と依頼したのに、本体を書き換えられた。
- 「確認しました、問題ありません」とだけ返ってきた。
- レビューを依頼したら、こちらの結論を追認する報告が返ってきた。
- 報告の数字をそのまま使ったら、委譲先も別の報告から写しただけだった。

原因の多くは委譲先の能力ではなく、指示書に書かれていなかったことと、受け取った側が確認しなかったことにあります。このスキルは、その 2 か所の手順を定めます。

## 使い方

名前を出して依頼します。

```
/delegate-seyo この調査を 3 つに分けて、並行で調べさせて
```

```
delegate-seyo の手順で、この報告書の数値を別のエージェントに確認させて
```

slide-seyo の手順の中からも呼び出されます。

## エージェントがすること

| 場面 | すること |
|---|---|
| 委譲する前 | 委譲するかどうかを決める。機械的に測定できる作業はスクリプトにし、数回の操作で済む作業は自分で行う |
| 指示書を書くとき | 目的、読む資料、書き込んでよい場所、読むだけか修正してよいか、完了の証拠、報告の形式を書く |
| 結果を受け取ったとき | 範囲外のファイルを変更していないか、結論を左右する主張が元の資料と一致するかを確認する |
| ユーザーに伝えるとき | 自分で確認したことと、委譲先の報告のままのことを、区別して伝える |

## プロジェクトの決まりを委譲先に伝える

プロジェクトに作業の決まり（変更してはいけないフォルダ、用語、承認が必要な操作）がある場合は、`CLAUDE.md`、`AGENTS.md`、`docs/` の下の文書に書いておきます。エージェントは関係する項目を指示書に写して委譲先に渡します。依頼のときにファイルを指定しても構いません。

## 同梱のスクリプト

`scripts/scope_check.py` は、委譲した作業が許可した範囲の外のファイルを変更していないかを一覧にします。git で管理しているフォルダで使い、Python の標準ライブラリだけで動きます。

```
python scripts/scope_check.py --allow "docs/report/**" --allow "scripts/check_*.py"
python scripts/scope_check.py --selftest
```

確認するのはどのファイルが変更されたかだけで、変更の内容は差分で確認します。

## このスキルが扱わないこと

- 指示書とユーザーへの報告の文章の基準。論述の層（ronjutsu-seyo）と文体の層（buntai-seyo）が扱い、エージェントは指示書と報告を書く前に、文書の種類を指定してそれらを読みます。2 つの層が設置されていなければ、手順と検査だけが働きます。
- エージェントを起動するツールそのものの操作方法。使っているツールの手引きに従ってください。
- どのモデルを使うか。モデルの名前は時期によって変わるので、このスキルには書いていません。作業の性質（事実の収集か、判断が必要な確認か）で選ぶという考え方だけを書いています。

## 起動の設定

名前を出して頼んだときだけ使われるよう、説明文で指定しています。Claude Code では、`settings.json` の `skillOverrides` で `name-only` にすると、説明文も一覧から外れます。プラグインで入れた場合、この設定は効きません。

```json
{ "skillOverrides": { "delegate-seyo": "name-only" } }
```

## アンインストール

スキルの削除は、入れた方法ごとに、リポジトリの `docs/install.md` の「削除」の手順で行います。`settings.json` の `skillOverrides` に `"delegate-seyo"` の行を足していれば、それも削除します。

削除せずに無効化する場合は、`skillOverrides` の値を `"off"` にします。

## ファイルの構成

```
delegate-seyo/
├─ SKILL.md                  エージェントが読む本体
├─ README.md                 このファイル
├─ references/
│  ├─ brief.md               指示書のひな形と、良い例・悪い例
│  └─ acceptance.md          結果の確認方法、レビューの指摘の扱い
└─ scripts/
   └─ scope_check.py         範囲外の変更の一覧
```
