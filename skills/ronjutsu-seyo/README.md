# ronjutsu-seyo（論述の層）

論理で読ませる文章（論文、発表、報告、メール、AI 向けの文書）について、何をどの順で主張するかの方針をまとめたスキルです。語と表記は、対になる buntai-seyo（文体の層）が扱います。

このファイルは人が読むための説明です。エージェントが読むのは `SKILL.md` です。

## 構成

| 部品 | 役割 | 公開 |
|---|---|---|
| ronjutsu-seyo | 論述の層。どの書き手にも当てはまる方針 | する |
| buntai-seyo | 文体の層。文書の種類で基準を切り替える | する |
| 図鑑（`~/.seyo/projects/<プロジェクト>/genten.md`） | 1 人の利用者が AI の文章と進め方に出した指摘の原文。プロジェクトごとに置き、上限は設けない | しない |
| chosei-seyo | 利用者が会話で出した指摘を取り出し、原文を図鑑に登録する | する |

作業の手順を持つスキル（slide-seyo、delegate-seyo）は、文章を書く場面で、文書の種類を指定してこの 2 つの層を読むよう案内します。方針を作業のスキルから分けたのは、作業の手順は誰が使っても同じで、何を良い文章とするかは人と場面で異なるからです。

## 使い方

名前を出して頼みます（「ronjutsu-seyo で、この節を書き直して」）。エージェントは、文章の種類を決め、論述の層、文体の層、そのプロジェクトの図鑑（書く文書の種類の節と「進め方」の節）の順に読んでから書きます。

## 測定で分かっていること

作者 1 人の記録（論文の推敲と、発表の準備で AI の文章に出した指摘）で測定しました。試験は、利用者が読んでいた文章を別のモデルに見せ、利用者が指摘した問題を挙げられるか（指摘の再現）と、書き直しでその問題が解消するか（書き直し）を測ります。手順は、同じリポジトリの `harness/PROCEDURE.md` にあります。

| 問い | 結果 |
|---|---|
| 取り込んだ指摘を、同じ材料で再現できるか（指摘を言い換えてまとめた文書を渡した場合。以下同じ） | できます。再現率は、論文の推敲の記録で 15.6% → 52〜53%、発表の準備の記録で 25.2% → 44.3% |
| 取り込んだあとの新しい材料に、利用者が出す指摘を予測できるか | できません。+3.0 ポイントで、95% の区間は 0 を含みます |
| 新しい材料の草稿を書き直すと、指摘された問題は減るか | 減ります。解消率は 12.8% → 26.6%（差の 95% の区間は +0.3〜+30.2）。ただし 27 件中 18 件は解消しませんでした |
| 副作用 | 文章の確認に使うと、利用者が直さなくてよいと決めた箇所を問題として挙げる件が増えました（18 か所中 3 → 7） |

白紙から文章を書くときに指摘が減るかどうかは、この試験では測っていません。

指摘を言い換えてまとめた文書が、原文を読ませる方法を上回った測定はありませんでした（取り込み済みの材料で 52〜53% 対 59.1%、新しい材料で 31.6% 対 36.0%。後者の差は 95% の区間が 0 を含みます）。そのため、利用者ごとの指摘は、言い換えずに原文のまま図鑑に置く形にしています。図鑑の形そのものは測定していません。

## この層の作り方

層の本文は、利用者の指摘の記録から chosei-seyo の保守者向けの手順（`../chosei-seyo/references/maintainer.md`）で作成したもので、手で書き足していません。本文を変えるときは、指摘の記録から作り直します。
