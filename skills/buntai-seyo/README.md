# buntai-seyo（文体の層）

語の選び方、文の構成、強調、表記の基準を、文書の種類ごとに定めたスキルです。何をどの順に主張するかは、対になる ronjutsu-seyo（論述の層）が定めます。

このファイルは人が読むための説明です。エージェントが読むのは `SKILL.md` です。

## 基準の分け方

`SKILL.md` の第 1 節はすべての文書に共通の基準です。第 2 節は文書の種類ごとの基準で、第 1 節と併せて適用します。種類は、論文、発表、査読への回答、報告、README などの付属文書、AI 向けの文書などです。種類の名前は論述の層と共通です。

一つの文体をすべての種類に適用すると、技術文書は平易すぎる文になり、発表の台本は読み言葉になります。そのため種類ごとに基準を切り替えます。たとえば発表の台本では、聞き手が一度で理解できる長さの文にします。論文の文の長さの規約は台本に適用しません。

語は和語か漢語かではなく、その分野で定着しているかどうかで選びます。定着した語を和語や口語に言い換えると、読み手は元の語を推測しなければならないからです。

## 悪い例と良い例

`references/examples.md` に、規則ごとの悪い例と良い例があります。エージェントは判断に迷ったときに読みます。主題（「〜は」）の直後に読点を打つかどうかの判断の表も、このファイルにあります。

## 使い方

名前を出して頼みます。

```
buntai-seyo で、この README を直して
```

エージェントは文書の種類を決め、文体の層を読みます。論理的な文章であれば、論述の層も同じ種類について読みます。作業中のプロジェクトに利用者の指摘の図鑑があれば、図鑑も読んでから書きます。slide-seyo と delegate-seyo は、文章を書く場面でこの層を読むようエージェントに指示します。

二つの層と図鑑の関係はリポジトリの [README](../../README.md#仕組み) にあります。測定の結果は [ronjutsu-seyo の README](../ronjutsu-seyo/README.md#測定で分かっていること) にあります。
