# 依頼: 回の候補を、原文の図鑑に登録する

この指示書は、chosei-seyo の登録の担当が読む。SEYO_HOME、プロジェクトのキー、chosei-seyo のフォルダ、回の名前は、依頼文の最後に書いてある。以下、`<P>` は `<SEYO_HOME>/projects/<キー>/` を、`<回>` は `<P>/chosei/rounds/<回の名前>/` を、`<スキル>` は chosei-seyo のフォルダを指す。コマンドには `--home <SEYO_HOME> --project <キー>` を付ける。

## 1. 目的

図鑑（`<P>/genten.md`）は、文章を書くエージェントが、論述と文体の層のあとに読む文書である。利用者が AI の文章と進め方に出した指摘の原文を、文書の種類と主題の見出しの下に、改変せずに引いてある。読む AI は、引用から、その位置で何が問題だったかを読み取る。作者の測定では、指摘を言い換えてまとめた文書は、原文を読ませる方法を上回らなかった。AI の添え書きを足すほど、読む AI が読む言い換えが増える。そのため、引用はそのまま置き、添え書きは原則として付けない。

この依頼では、回の候補（会話から取り出し、照合を通した指摘）を 1 つずつ、図鑑に登録するか外すかを決め、登録するものを図鑑の案に足す。外した候補は、図鑑を読む AI に届かない。外す理由は 5 節の 4 つに限り、迷ったら登録する。

## 2. 読むもの

- 回の候補: `<回>/cand_*.jsonl` のすべて。1 行が 1 つの候補で、使う欄は id、user_words（利用者の発言の写し）、doc_kind（文書の種類）、limits（当てはまらない場合、利用者の限定、取り下げ、経過）、judgment と applies_to と ai_pattern（何についての指摘かを知るため。図鑑には書かない）である。欄の意味は `<スキル>/references/data.md` の 6 節にある。
- 図鑑の案: `<回>/genten.draft.md`。3 節の 1 で、いまの図鑑の写しとして作る。

これ以外のファイル（控えの entries.jsonl、対話、記録、ほかの回）は開かない。照合は、引用を控えの写しと比べて確かめるので、ほかの資料から足した判断は確かめられないまま図鑑に入る。

## 3. 手順

1. 案を作る。`python <スキル>/scripts/check_genten.py --round <回の名前> --start`。案は、いまの図鑑の写し（図鑑が無ければ、読み方だけのひな形）になる。前の試みの案が残っていると断られるので、作り直すなら `--force` を付ける。
2. 候補ごとに、登録するか外すかを決める（5 節）。
3. 登録する候補の写しを、案に足す（4 節の形）。足すときは Edit ツールで、既にある行を書き換えずに挿入する。
4. 外した候補を `<回>/excluded.jsonl` に、1 行 1 件の JSON で書く。`{"id": "<回の名前>:c01-02", "reason": "取り下げられた指摘", "note": ""}` の形で、reason は 5 節の 4 つのどれかを一字も変えずに書く。note は任意で、「既に同じ原文が図鑑にある」なら、図鑑にある引用の id を書く。Write ツールで書く。外す候補が無ければ、空のファイルを書く。
5. 照合する。`python <スキル>/scripts/check_genten.py --round <回の名前>` の問題が 0 件になるまで直す。`--install` は付けない。設置は、照合を通ったあとに依頼者が行う。

## 4. 図鑑の形

```
## 進め方

### 編集の前の確認

> どの作業でも、編集する前に案を見せてほしい
<!-- 2026-05-21-0930:c01-03 -->

### 頼まれた範囲

> 頼んだ範囲で直して
<!-- 2026-05-23-1015:c01-01 -->
（注: 雨天の扱いの文を足す依頼で、連絡方法までは頼まれていなかった。）
```

- 第 2 階層の見出し（`## `）は、候補の doc_kind の値をそのまま書く。案にその見出しが無ければ作る。並びは、論文、発表、報告、査読への回答、メール、AI 向けの文書、付属文書、一般の読み手への説明、進め方、その他の順にする。
- 第 3 階層の見出し（`### `）は主題で、40 字以内の短い名詞句にする。「〜すること」「〜しない」のような規則や文の形にしない。見出しが規則に見えると、読む AI は引用ではなく見出しを規則として当てはめるからである。分類はあなたの整理でよく、読み方にもそう書いてある。同じ主題の指摘は、その種類の節に既にある見出しの下に足し、同じ見出しを 2 つ作らない。見出しを作る前に、その節の見出しをすべて読む。
- 見出しの下に、候補の user_words を、1 つの写しごとに 1 つの引用として置く。各行の先頭に `> ` を付け、写しの中の空行は `>` だけの行にする。写しを縮めたり、つないだり、誤字を直したりしない。1 つの候補から複数の写しを置いてよい。指摘の理由や条件を含む写しは省かない。
- 引用のすぐ次の行に、その候補の id を `<!-- <回の名前>:<候補の id> -->` の形で書く。照合と、どの指摘が登録済みかの追跡に使う。
- 注は、引用だけでは利用者が限定した範囲の外まで当てはめられるおそれがある場合にだけ、id の行のすぐ次に 1 行で「（注: …）」と書く。注に書けるのは、その候補の limits にある境界と経過だけで、limits が空の候補には注を付けない。何についての指摘か、指摘された AI の振る舞い、あなたの解釈は書かない（それらは控えに残っている）。
- 引用、id、注のまとまりの間は空行で区切る。
- 案に既にある引用、id、注、見出し、冒頭の読み方は、変更も削除も移動もしない。足すだけである。照合は、前の版のまとまりがすべて同じ見出しの下に残っているかを確かめる。

## 5. 外す理由

外すのは次の 4 つに当たる候補だけである。迷ったら登録する。

| 理由 | 当たる候補 |
|---|---|
| 返事だけの発言 | 了解や承認だけで、何を問題にしたかが写しから読めない（ふつうは候補になっていない） |
| その文書だけの決定 | 特定の図の番号、特定の段落の扱いのように、ほかの文書に移せない決定。決定の理由が一般の判断を示していれば登録する |
| 取り下げられた指摘 | 利用者が指摘そのものを取り下げた（limits に書かれている）。指摘に条件や限定が付いただけなら取り下げではないので、登録して注を付ける。AI の反論を利用者が受け入れた出来事を記録した候補は、直さない境界を示すので登録する |
| 既に同じ原文が図鑑にある | 同じ写しが既に引かれている。似た趣旨の別の発言は、利用者が繰り返した指摘なので、同じ主題の見出しの下に登録する |

分量や重要度の低さ、一般的に見えることは、外す理由にならない。

## 6. してはいけないこと

- 書き込むのは `<回>/genten.draft.md` と `<回>/excluded.jsonl` だけにする。`<P>/genten.md` と控えは書き換えない。
- 2 節のもの以外を開かない（この指示書と照合のスクリプトは除く）。
- 候補には、利用者の作業の内容と個人の発言が含まれる。Web 検索と外部のサービスを使わない。環境変数を一覧で表示しない。

## 7. 報告

最後の返答に、次を 300 字以内で書く。

1. 候補の数、登録した数、外した数（理由ごと）、照合の結果。
2. 新しく作った見出し（種類と主題）。
3. 登録するか外すかで迷った候補と、その決め方。
4. この指示書どおりに進めると誤った結果になると考えた点。
