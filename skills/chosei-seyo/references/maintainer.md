# 既定の改訂（スキルの保守者の作業）

利用者が行う取り込みは、その利用者の図鑑だけを変える。論述の層（ronjutsu-seyo）と文体の層（buntai-seyo）は、すべての利用者が読む公開の既定であり、改訂するのはスキルの保守者である。材料の取り出しは取り込みと同じで、記録と候補の段を通る。違うのは、材料の出どころ、作成の担当が書く文書と出力先、公開の前の確認である。層は公開するので、図鑑と違い、利用者の原文を入れられない。

## 1. 材料

- 保守者自身の会話を、`SKILL.md` の 4 節の手順で回にし、候補まで取り出す。候補は `$SEYO_HOME/projects/<キー>/chosei/rounds/<回>/cand_*.jsonl` にあり、照合を通した候補の全部は `$SEYO_HOME/projects/<キー>/entries.jsonl`（控え）にある。図鑑は登録の担当が選んだ一部なので、材料には控えを使う。
- ほかの利用者の候補は、その利用者が公開の材料にすることに同意したものだけを使う。候補の user_words は利用者の発言の写しなので、公開する文書には入れない。
- 既定に入れるのは、その判断を知らない書き手にも、理由を説明すれば同意が得られる内容に限る。1 人の利用者だけに現れる重みづけと好みは、その利用者の図鑑に残す。既定に入れると、その判断を持たない利用者の文章まで、その向きに直されるからである。

## 2. 作成の担当への指示書

作成の担当（サブエージェント）への指示書は、保守者が作業ごとに書く。次の項目を入れる。

| 項目 | 内容 |
|---|---|
| 目的 | 層の既定を、新しい候補に照らして改訂する。層は書く前と書いたあとの両方に使われる |
| 読むもの | いまの層の本文（ronjutsu-seyo と buntai-seyo の文書）、前の改訂の設計の記録、新しい候補（控えの項目か `cand_*.jsonl`） |
| 作るもの | 層の改訂版と設計の記録（どの候補にもとづくか、入れなかった強い候補とその理由）。出力先は層のスキルの作業ツリーで、`SEYO_HOME` ではない |
| 長さ | 論述の層は 7,000 字以内、文体の層は 5,000 字以内 |
| 公開の条件 | 下の箇条書き |

公開の条件は次のとおりで、指示書の「守ること」に理由と一緒に書く。

- 利用者の発言の引用、利用者の作業の内容と固有名、利用者独自の言い回しを入れない。利用者が独自の語で呼んでいる考え方は、一般の言葉で書く。公開の文書は、その利用者を知らない書き手が読む。
- 禁止の一覧にしない。何を目指すか、なぜか、書いたものをどう確認するかを書き、項目に理由を添える。理由のない規則は、当てはめすぎの原因になる。
- 書く前（何を伝える文書かを決め、主張の筋を作る）と、書いたあと（読み直して問題を見つける）の両方に使えるようにする。読み直しの部分は、問題を見つけるための問いの形でもよい。
- 文書の種類（論文、発表、報告や説明の返答、依頼文など）で判断が変わる所は、どう変わるかを書く。資料の判断から導けない一般論は加えない。
- 方針の持ち方（目的を規則より優先すること、1 回の指摘を全体の禁止に広げないこと、手本や慣例は記憶ではなく実物で確認すること）を保つ。
- 例を作らない。例が要る所は、どういう形の文かを言葉で説明する。作り物の例は、実際の失敗と違う形になりやすい。公開する実例を加える場合は、公開できる題材について AI に書かせた出力から、原則が指す失敗が実際に現れたものを選ぶ。
- 文体の層は、文書の種類で基準を切り替える形を保つ。日本語の文章の一般の規範と重なる内容は要点だけを書き、論述の層と重なる内容は書かない。
- 一般の規範と利用者の判断が食い違う場合は、既定に一般の側を書き、利用者の側はその利用者の図鑑に残す。

## 3. 公開の前の確認

- 字数と、論述の層と文体の層の間の重複。
- 公開できない語の検索。材料にした利用者の固有名、作業の名前、パス、利用者独自の語の一覧を、保守者が非公開で持ち、改訂版に対して検索して 0 件にする。一覧はスキルのフォルダに置かない。
- 作成の担当とは別の検査の担当に、改訂版と候補だけを読ませ（設計の記録は渡さない。読むと追認する検査になる）、項目ごとに、境界の欠け、広げすぎ、根拠の無さを判定させる。既定では、1 人の利用者の 1 回の指摘を一般の方針に広げる誤りが、1 人の図鑑より重い影響を持つ。
- 検証を行う場合は、`kensho.md` の手順で、改訂の前後の解消率（書き直し）と再現率（指摘の再現）を比べる。
- 層のスキルの変更の記録に、何をなぜ変えたかを書く。
