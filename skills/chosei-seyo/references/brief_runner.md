# 依頼: 検証の測定を実行する（受験と採点の担当を起動し、結果を集める）

この指示書は、chosei-seyo の検証で、受験の担当と採点の担当を起動して回答と採点を集める実行役が読む。SEYO_HOME、プロジェクトのキー、chosei-seyo のフォルダ、測定の名前、受験の担当のモデルと設定、採点の担当のモデルと設定は、依頼文の最後に書いてある。以下、`<スキル>` は chosei-seyo のフォルダを、`<測定>` は測定の名前を、`<P>` は `<SEYO_HOME>/projects/<キー>/` を指す。コマンドには `--home <SEYO_HOME> --project <キー>` を付ける。

判断の要る作業は無い。決められた手順を抜けなく実行することが仕事である。依頼者は文脈が大きく、数十から百を超える担当の完了の知らせを自分で受けると使用量を大きく消費するので、この作業を任せている。

## 1. 守ること（測定を壊さないため）

- 試験の中身を読まない。読んでよいのは、この指示書とコマンドの出力だけである。`<P>/chosei/exam/` の下（単位、plan.json、grade_key_*.json、回答、採点）と、作業フォルダの中の問題、回答、採点のファイルは開かない。条件の名前と回答の対応を知らないまま進めることに意味がある。
- 受験の担当と採点の担当への依頼文は、コマンドが表示した文を一字も変えずに使う（符号は表示のとおりに入れ替える）。説明や助言を足さない。作者の測定と同じ文面でなければ、結果を比べられない。
- 結果の数値を見て、手順を変えない。数値がどうであっても、同じ手順を最後まで行う。
- 受験の担当は、依頼文に書かれたモデルと設定で、全員同じにする。採点の担当も同じく、依頼文のモデルと設定にする。
- 書き込みは、下のコマンドが行うものだけにする。ファイルを自分で編集しない。
- 環境変数を一覧で表示しない。Web 検索と外部のサービスを使わない。

使用量の上限に近づいたという知らせを受けたら（担当の返事が「完了」でなく、使用量に触れている場合も含む）、新しい担当を起動せず、実行中の担当が終わるのを待つ。その担当を起動し直さない。上限が戻ってから、未完了のものを調べる所から続ける。同時に動かす担当は、受験で 8 つ、採点で 5 つまでにする。知らせのあとに、実行中の担当が残りを使い切らないようにするためである。

## 2. 受験

1. `python <スキル>/scripts/exam_run.py pending <測定>` で未完了の job と、それぞれの依頼文を表示する。
2. 未完了の job ごとに受験の担当を 1 つ起動し、表示された依頼文を渡す。8 つ起動し、終わるたびに空いた分だけ次を起動する。
3. すべて終わったら、もう一度 `pending` を実行する。残っている job は `exam_run.py reset-job <測定> <符号>` で回答を消してから、同じ依頼文で起動し直す。一部だけ回答した job も、消してから最初からやり直す。やり直しは job ごとに 2 回までとし、それでも残る job は報告に書く。
4. `exam_run.py collect <測定>` で回答を集め、「欠け 0 件」を確かめる。

## 3. 採点（1 人目の採点者 g1。すべての資料）

1. `exam_run.py grade-prepare <測定> g1` で資料を作る。束ごとの依頼文が表示される。
2. 束ごとに採点の担当を 1 つ起動し、その束の依頼文を渡す。同時に 5 つまでにする。
3. すべて終わったら `exam_run.py grade-pending <測定> g1` を実行し、残った資料の束を、表示された依頼文で起動し直す（2 回まで）。
4. `exam_run.py grade-collect <測定> g1` で採点を集め、「欠けのある資料 0 件」を確かめる。

## 4. 採点（2 人目の採点者 g2。3 つに 1 つの資料）

`exam_run.py grade-prepare <測定> g2 --every 3` で資料を作り、3 と同じ手順で採点させ、`grade-collect <測定> g2` で集める。依頼文に 2 人目のモデルの指定があれば、それを使う。

## 5. 集計

```
python <スキル>/scripts/exam_run.py aggregate <測定>
python <スキル>/scripts/exam_run.py breakdown <測定>
```

結果は `<P>/chosei/exam/runs/<測定>/` の `result_g1.md` と `breakdown_g1.md` に書かれる。

## 6. 報告

最後の返答に、次を 300 字以内で書く。集計の数値は書かなくてよい。

- 受験: job の数、やり直した job の数、最後まで残った未完了の job。
- 採点: g1 と g2 の資料の数、やり直した数、欠けの残った資料。
- 使用量の知らせで中断した回数。
- 手順どおりに進まなかった点。
