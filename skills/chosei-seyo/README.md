# chosei-seyo

AI に書かせた文章と AI の進め方に対して、あなたが会話の中で出した指摘を、プロジェクトごとの原文の図鑑に取り込むスキルです。図鑑は、あなたの指摘の原文を、文書の種類と主題の見出しの下に改変せずに引いた文書で、公開の既定である論述の層（ronjutsu-seyo2）と文体の層（buntai-seyo）のあとに読まれます。

このファイルは人が読むための説明です。エージェントが読むのは `SKILL.md` です。

## 測定で分かっていること

作者 1 人の記録で、このスキルの以前の形（指摘を別の担当が言い換えて、利用者全体で 1 つの短い文書にまとめる形）について測った結果です。ほかの利用者で同じ結果になるかは測っていません。「指摘の再現」は、利用者が読んでいた文章を見せて、利用者が指摘すると考える問題を件数の上限つきで挙げさせます。「書き直し」は、同じ文章を書き直させ、利用者が指摘した問題が解消したかを判定します。

| 問い | 結果 |
|---|---|
| 取り込んだ指摘を、同じ材料で再現できるか | できる。再現率は、論文の推敲の記録で 15.6% → 52〜53%、発表の準備の記録で 25.2% → 44.3% |
| 取り込んだあとの新しい材料に、利用者が出す指摘を予測できるか | できない。+3.0 ポイントで、95% の区間は 0 を含む |
| 言い換えてまとめた文書は、原文を読ませる方法を上回るか | 上回った測定は無い。取り込み済みの材料で 52〜53% 対 59.1%、新しい材料で 31.6% 対 36.0%（後者の差の 95% の区間は 0 を含む） |
| 新しい材料の草稿を書き直すと、指摘された問題は減るか | 減る。解消率は 12.8% → 26.6%（差の 95% の区間は +0.3〜+30.2）。ただし 27 件中 18 件は解消しなかった |
| 副作用 | 利用者が「直さなくてよい」と決めた箇所を問題として挙げる件が増えた（18 か所中 3 → 7）。書き直しで壊した件は 0 |

言い換えてまとめる形が原文を上回らなかったので、このスキルは原文を引く形に変えました。いまの形（担当が候補から原文を選び、主題の見出しの下に引いた図鑑）そのものは測っていません。図鑑は、あなたが次に出す指摘を予測する道具ではなく、出した指摘をあとの会話や別のエージェントに引き継ぎ、同じ指摘の繰り返しを防ぐ道具として使います。そのため、作業の途中で指摘が出るたびに少しずつ取り込む使い方を主にしています。

## 使い方

### 作業の途中で

AI に指摘をしたあと、同じ会話で「chosei-seyo で取り込んで」と頼みます。エージェントが、いまの会話のまだ取り込んでいない発言から指摘を取り出し（候補）、照合を通したものを控えに足し、登録の担当が残す価値のある原文を図鑑に引きます。確認は求められず、完了の報告に、図鑑に登録した件（見出しと引用の最初の行）と、外した件（理由つき）が示されます。外した件を入れたければ「これも入れて」と言えば足されます。

範囲は、そのプロジェクトで前に取り込んだ所の続きから、あなたの最後の発言までです。「今日の分だけ」のように範囲の始まりを指定することもできます。

### まとめて取り込む

長い作業のあとや、複数の会話をまとめて取り込むときは「chosei-seyo でまとめて取り込んで」と頼みます。取り込みの済んでいない会話の一覧から選ぶと、エージェントがサブエージェントで記録、点検、候補、登録を進めます。プロジェクトで初めての取り込みでは、検証（取り込みの効果の測定）を行うかを尋ねられます。

### プロジェクトと共通の図鑑

プロジェクトは、作業フォルダ（git の作業ツリーならその最上位）の名前で決まります。同じ名前で場所の違うフォルダでは、エージェントがどのプロジェクトかを尋ねます。どのプロジェクトでも読ませたい指摘は、共通の図鑑に移せます。取り込みの報告の最後に、共通に移す候補が示されることがあります（あなたの発言に「いつも」「どの作業でも」のような範囲を述べた語がある場合と、別のプロジェクトの図鑑に近い発言がある場合だけです）。移すのは、あなたが指示した項目だけです。文章を書くエージェントは、プロジェクトの図鑑では書く文書の種類の節と「進め方」の節だけを読みますが、共通の図鑑は節を問わず全体を読みます。指摘は元のプロジェクトでの種類の節（たとえば「報告」）に置かれたまま移るので、種類の節だけを読むと、別の種類の文書を書くときに読まれないからです。共通の図鑑にはあなたが選んだ項目だけが入るので、全体を読んでも分量は小さく保たれます。別のプロジェクトの図鑑を引き継がせたいときは、元のプロジェクトを名指しして頼みます。

### 取り消し

取り込んだ回を取り消すよう頼むと、その回の指摘が控えと図鑑から外れます。その範囲の発言は、次の取り込みでもう一度範囲に入ります。

## 仕組み

| 段 | 担当 | 出力 | 照合 |
|---|---|---|---|
| 記録（まとめて取り込むときだけ） | サブエージェント | 原稿への指摘と、進め方や返答への指摘の記録 | 写しが会話に一字一句あるか、反応の分類、範囲（`check_records.py`）。別の担当による点検 |
| 候補 | サブエージェント | 指摘ごとの候補（あなたの発言の写し、文書の種類、当てはまらない場合） | 写しがあなたの発言にあるか、根拠の記録があるか（`check_candidates.py`） |
| 控え | スクリプト（`install_round.py`） | 候補の全部の控え | 同じ回を 2 度足さない |
| 登録 | サブエージェント | 図鑑の案と、外した候補の一覧 | 引用が控えの写しと一字も違わないか、前の版の引用が残っているか、候補がすべて登録か外した一覧にあるか（`check_genten.py`） |

図鑑の引用はあなたの発言そのままで、AI の添え書きは、当てはめすぎを防ぐのに要る場合の 1 行の注だけです。登録の担当が候補を外せるのは、返事だけの発言、その文書だけの決定、取り下げられた指摘、既に同じ原文が図鑑にある、の 4 つの場合だけで、迷えば登録します。外した候補も控えには残ります。

## 置き場

あなたのデータは、スキルのフォルダの外の `~/.seyo/` に置かれます（環境変数 `SEYO_HOME` で変更できます）。スキルのフォルダには個人のデータが入らないので、スキルを更新しても、公開しても、データには影響しません。

| 場所 | 内容 |
|---|---|
| `~/.seyo/projects/<キー>/genten.md` | プロジェクトの図鑑 |
| `~/.seyo/projects/<キー>/entries.jsonl` | 取り出した指摘の全部の控え |
| `~/.seyo/projects/<キー>/project.json` | 作業フォルダの場所と、引き継ぐプロジェクト |
| `~/.seyo/projects/<キー>/chosei/` | 会話の抜き出し、取り込みの回、取り込み済みの範囲、検証 |
| `~/.seyo/common/` | 共通の図鑑と控え |

記録には、あなたの発言と作業の内容がそのまま入ります。このフォルダを共有のリポジトリや外部のサービスに置かないでください。文章を書くスキルは `scripts/seyo_where.py` で、読む図鑑の場所と節の行の範囲（共通の図鑑は全体を読むこと）を知ります。形式の詳細は `references/data.md` にあります。

## 検証

取り込みの効果を、あなたの記録で測る手順と道具を同梱しています（`references/kensho.md`、`scripts/check_exam.py`、`scripts/exam_run.py`）。任意で、費用が大きい作業です。作者の環境では、100 件の受験とその採点に、定額プランの 5 時間の使用枠を 2 つ分ほど使いました。検証には、取り込んでいない時期の会話が要ります。あとで検証するつもりなら、その時期の会話は、測り終えるまで取り込まないでください。

## 動作の確認

```
python -B scripts/selftest.py
```

架空の会話（町内会の清掃と防災訓練のお知らせを AI に書かせる会話）で、抜き出し、範囲、記録と候補の照合、控えへの設置、図鑑の照合と設置（登録の担当の案は作り物）、名指しの登録、取り消し、プロジェクトの決め方、引き継ぎと読む場所、共通に移す候補、古い形式の候補の移行、進行中の会話の範囲、検証の試験の照合から集計まで（回答と採点も作り物）を一通り動かします。全項目が通ると「selftest: 全 N 項目が通った」と表示します。Python 3 の標準ライブラリだけで動きます（作者が確認したのは 3.14 です）。

## 分かっている限界

- 効果の測定は、作者 1 人の記録で、このスキルの以前の形に対して行ったものです。いまの形（原文を選んで引いた図鑑）は測っていません。
- 図鑑に引く原文は登録の担当が選び、見出しの分類も担当の整理です。外す理由は 4 つに限っていますが、担当がその当てはめを誤ると、残すべき指摘が図鑑に届きません。外した件は報告に示されるので、必要なら名指しで足してください。
- 作業の途中の取り込み（記録の段を省き、数件ずつ取り込む経路）は測っていません。
- 進行中の会話は、記録が 10 分以内に更新されたかで見分けます。終わった直後の会話も進行中とみなされ、最後の発言より後の発言は次の回に回ります（失われはしません）。
- 対応する記録の形式は、Claude Code のセッションの jsonl です。Codex の記録や貼り付けた対話は、抜き出しと同じ形の md に直せば使えます（形式は `references/data.md` の 2 節）。
- 会話を分岐させた記録の重複は、同じプロジェクトの中で、同じ時刻と同じ本文の発言として見つけます。
- 論述の層と文体の層のスキルが図鑑を読むかは、それぞれのスキルの説明を確認してください。図鑑の場所は `scripts/seyo_where.py` が示します。
- まとめて取り込む経路では、セッションの数と長さに応じた数のサブエージェント（記録、点検、候補、登録）が動きます。

## アンインストール

このフォルダを削除します。`~/.seyo/` のデータは残るので、不要なら削除してください。
