# chosei-seyo

AI の文章と進め方に利用者が出した指摘を、会話から取り出して原文の図鑑に取り込むスキルです。図鑑はプロジェクトごとに置きます。図鑑には利用者の指摘の原文を、文書の種類と主題の見出しの下に改変せずに引きます。文章を書くエージェントは、論述の層（ronjutsu-seyo）と文体の層（buntai-seyo）を読んだあとに図鑑を読みます。

このファイルは人が読むための説明です。エージェントが読むのは `SKILL.md` です。

図鑑は、利用者が次に出す指摘を予測する道具ではありません。出た指摘をあとの会話や別のエージェントに引き継ぎ、同じ指摘の繰り返しを防ぐ道具です。そのため、作業の途中で指摘が出るたびに取り込む使い方を主にしています。

## 使い方

### 作業の途中で

AI に指摘をしたあと、同じ会話で「chosei-seyo で取り込んで」と頼みます。エージェントは次の順に進めます。

1. いまの会話のまだ取り込んでいない範囲から指摘を取り出し、候補にして照合します。
2. 照合を通した候補をすべて控えに足します。控えへの追加には確認を求めません。
3. 登録の担当が、残す価値のある原文を図鑑の案に引きます。
4. 登録する件と外す件を利用者に示し、返答を待ちます。
5. 利用者が了承すると、図鑑に設置して報告します。

エージェントは登録する件を見出しと引用の最初の行で示し、外す件を理由つきで示します。外す件を入れたいときは、その件を名指しします。

範囲は、同じプロジェクトで前に取り込んだ範囲の続きから、利用者の最後の発言までです。「今日の分だけ」のように範囲の始まりも指定できます。

### まとめて取り込む

長い作業のあとや、複数の会話をまとめて取り込むときは「chosei-seyo でまとめて取り込んで」と頼みます。取り込みの済んでいない会話の一覧から利用者が選ぶと、エージェントはサブエージェントに記録・点検・候補・登録を任せます。図鑑への設置は、作業の途中の取り込みと同じく、案を示して了承を得てから行います。プロジェクトで初めての取り込みでは、検証を行うかを尋ねます。検証とは、取り込みの効果の測定です。

### プロジェクトと共通の図鑑

プロジェクトは作業フォルダの名前で決まります。git の作業ツリーでは、その最上位のフォルダの名前です。同じ名前で場所の違うフォルダでは、エージェントがどのプロジェクトかを尋ねます。

どのプロジェクトでも読ませたい指摘は共通の図鑑に移せます。移すのは利用者が指示した項目だけです。設置の報告の最後に、共通に移す候補が示されることがあります。候補になるのは、発言に「いつも」「どの作業でも」のような範囲を述べた語がある場合と、別のプロジェクトの図鑑に近い発言がある場合です。

文章を書くエージェントは、プロジェクトの図鑑では書く文書の種類の節と「進め方」の節を読みます。共通の図鑑は全体を読みます。指摘が元のプロジェクトでの種類の節に置かれたまま移るからです。種類の節だけを読むと、別の種類の文書を書くときに移した指摘が読まれません。共通の図鑑には利用者が選んだ項目だけが入るので、全体を読んでも分量は小さく済みます。

別のプロジェクトの図鑑を引き継がせたいときは、元のプロジェクトを名指しして頼みます。

### 取り消し

取り込んだ回を取り消すよう頼むと、その回の指摘が控えと図鑑から外れます。取り消した回の範囲の発言は、次の取り込みでもう一度範囲に入ります。

## 仕組み

| 段 | 担当 | 出力 | 照合 |
|---|---|---|---|
| 記録（まとめて取り込むときだけ） | サブエージェント | 原稿への指摘と、進め方や返答への指摘の記録 | 写しが会話に一字一句あるか、反応の分類、範囲（`check_records.py`）。別の担当による点検 |
| 候補 | サブエージェント | 指摘ごとの候補（利用者の発言の写し、文書の種類、当てはまらない場合） | 写しが利用者の発言にあるか、根拠の記録があるか（`check_candidates.py`） |
| 控え | スクリプト（`install_round.py`） | 候補の全件の控え | 同じ回を二度足さない |
| 登録 | サブエージェント | 図鑑の案と、外した候補の一覧 | 引用が控えの写しと一字も違わないか、前の版の引用が残っているか、候補がすべて登録か外した一覧にあるか（`check_genten.py`） |
| 設置 | スクリプト（`check_genten.py --install`） | 図鑑 | 利用者が案を了承してから設置する |

図鑑の引用は利用者の発言そのままです。AI の添え書きは、当てはめすぎを防ぐのに要る場合の 1 行の注だけです。登録の担当が候補を外せるのは次の 4 つの場合だけで、迷えば登録します。

- 返事だけの発言
- その文書だけの決定
- 取り下げられた指摘
- 既に同じ原文が図鑑にある

外した候補も控えには残ります。

## 置き場

利用者のデータはスキルのフォルダの外の `~/.seyo/` に置かれます。場所は環境変数 `SEYO_HOME` で変えられます。スキルのフォルダには個人のデータが入らないので、スキルを更新しても公開しても、データには影響しません。

| 場所 | 内容 |
|---|---|
| `~/.seyo/projects/<キー>/genten.md` | プロジェクトの図鑑 |
| `~/.seyo/projects/<キー>/entries.jsonl` | 取り出した指摘の全件の控え |
| `~/.seyo/projects/<キー>/project.json` | 作業フォルダの場所と、引き継ぐプロジェクト |
| `~/.seyo/projects/<キー>/chosei/` | 会話の抜き出し、取り込みの回、取り込み済みの範囲、検証 |
| `~/.seyo/common/` | 共通の図鑑と控え |

記録には利用者の発言と作業の内容がそのまま入ります。このフォルダを共有のリポジトリや外部のサービスに置かないでください。文章を書くスキルは、読む図鑑の場所と節の行の範囲を `scripts/seyo_where.py` で調べます。形式の詳細は `references/data.md` にあります。

## 測定

測定の結果は [ronjutsu-seyo の README](../ronjutsu-seyo/README.md#測定で分かっていること) にあります。測ったのはこのスキルの以前の形で、利用者の指摘を別の担当が言い換え、1 つの短い文書にまとめる形でした。言い換えてまとめた文書が原文を読ませる方法を上回った測定は無かったので、図鑑は原文を引く形にしました。原文を引く今の形はまだ測っていません。

## 検証

取り込みの効果を利用者自身の記録で測る手順と道具を同梱しています（`references/kensho.md`、`scripts/check_exam.py`、`scripts/exam_run.py`）。検証は任意で、費用の大きい作業です。作者の環境では、100 件の受験とその採点に、定額プランの 5 時間の使用枠を 2 つ分ほど使いました。

検証には、取り込みに使っていない時期の会話が要ります。あとで検証するつもりなら、その時期の会話は測り終えるまで取り込まないでください。

## 動作の確認

```
python -B scripts/selftest.py
```

架空の会話を使います。町内会の清掃と防災訓練のお知らせを AI に書かせる会話です。抜き出しと範囲の決め方、記録と候補の照合、控えへの設置、図鑑の案の照合と設置、名指しの登録、取り消し、プロジェクトの決め方と引き継ぎ、共通に移す候補、古い形式の候補の移行、検証の照合と集計を一通り動かします。登録の担当の案と、検証の回答と採点は作り物です。

全項目が通ると「selftest: 全 N 項目が通った」と表示します。Python 3 の標準ライブラリだけで動きます。作者が確かめたのは 3.14 です。

## 分かっている限界

- 図鑑に引く原文は登録の担当が選び、見出しの分類も担当が決めます。担当が外す理由の当てはめを誤ると、残すべき指摘が図鑑に届きません。外す件は設置の前に示されるので、必要なら名指しで足してください。
- 作業の途中の取り込みは測っていません。この経路は記録の段を省き、数件ずつ取り込みます。
- 進行中の会話は、記録が 10 分以内に更新されたかで見分けます。終わった直後の会話も進行中とみなされ、最後の利用者の発言より後の発言は次の回に回ります。発言は失われません。
- 読み取れる記録の形式は Claude Code のセッションの jsonl です。Codex の記録や貼り付けた対話は、抜き出しと同じ形の md に直せば使えます。形式は `references/data.md` の 2 節にあります。
- 会話を分岐させた記録の重複は、同じプロジェクトの中で、同じ時刻と同じ本文の発言として見つけます。
- まとめて取り込む経路では、セッションの数と長さに応じた数のサブエージェントが動きます。

## 削除

削除の手順は[導入の手引き](../../docs/install.md#削除)にあります。図鑑と記録を置いた `~/.seyo/` は、スキルを削除しても残ります。
