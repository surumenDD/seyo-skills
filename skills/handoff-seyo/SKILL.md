# handoff-seyo

文脈が圧縮されると、合意した細部と、作業に臨む姿勢が失われる。継続書は、その二つを圧縮のあとも参照できるように残す文書である。最新の 1 本を読めば作業を再開できる状態を保つ。

## 1. いつ書くか

- コンテキストの使用率が高いという知らせを受けたとき。進行中の一手は途中で止めず、切りのよい所まで進めてから書く。
- 作業の大きな区切り（段階の完了、方針の転換）に達したとき。
- 利用者に頼まれたとき。

プロジェクトの規則や利用者の指示が承認を求めていれば、書く前に提案する。それ以外では承認を待たない。継続書は作業の記録であり、成果物の変更ではないからである。

## 2. どこに書くか

次の順で決める。

1. プロジェクトに決まりがあれば、それに従う（`CLAUDE.md`、`AGENTS.md`、計画の文書の指定）。
2. 既存の継続書があれば、同じフォルダに置く。
3. どちらもなければ、リポジトリ直下の `handoff/` に置く。

ファイル名は `HANDOFF_<YYYY-MM-DD>_<HHMM>.md` とする。既存の継続書は上書きせず、新しいファイルを作成する。

## 3. 何を書くか

最新の 1 本だけで再開できるように書く。前の継続書を読まないと分からない書き方をしない。前の継続書の内容のうち、まだ有効なものは新しい継続書に書き写す。

| 項目 | 内容 |
|---|---|
| 目的と完成の定義 | 何を達成する作業か。どうなれば完成か |
| 利用者の方針 | 利用者が、判断の姿勢や進め方について述べた発言。原文のまま引用する |
| 現在の状態 | 完了したこと。進行中のこと。実行中のバックグラウンドの作業と、その出力先 |
| 決定 | 主な決定を 1 行ずつ。理由は決定の記録を参照する |
| 変更してはいけないもの | 触れてはいけないファイル、守る手順 |
| 未決の点 | まだ決めていないこと。利用者の返事を待っていること |
| 次の一手 | 再開して最初に行う操作。具体的に書く |
| 読み直す文書 | 再開時に読む文書と、その順番 |

「読み直す文書」の見出しは `## 読み直す文書` とする。番号や「（この順）」は付けてよい。見出しの下に、1 行に 1 つの文書を、読む順に番号を付けて書く。文書の場所と、読む節を書く。フックは、この見出しの下の行を読み取って、圧縮の直後にそのまま示す。見出しの文言が違うと読み取れない。継続書に追記して読む文書が変わったときは、この項目も書き直す。

利用者の方針の項目は省略しない。作業の内容は記録や成果物から復元できるが、利用者が求めた判断の姿勢は、圧縮の要約では短い一般論に置き換わる。要約せず、利用者の言葉をそのまま残す。直近の注意ほど優先して引用する。

次のものは書かない。

- 退けた案の経緯と、作業の細かい履歴。継続書が長くなり、次の読み手が現在の状態を見失う。
- 作業を問わず通用する方針。方針の文書に置き、継続書からは参照だけする。

## 4. 書いたあと

継続書の場所を 1 行で利用者に伝える。作業は止めずに続ける。

## 5. 再開するとき

文脈の圧縮の直後と、新しいセッションの最初に行う。

1. 最新の継続書を全文読む。
2. 「読み直す文書」に挙がっている文書を、指定された節まで、書かれた順にすべて読む。継続書は要点の写しであり、判定基準と決定の理由は、これらの文書にしかない。条件の付いた行は、その条件に当たるときに読む。
3. 次の返答の最初の行に、読んだ文書と節を書く（「再開時の読み直し: 文書（節）、文書（節）」の形）。読んでいない文書は書かない。利用者が読み飛ばしに気づけるようにするためである。
4. 作業に戻る。

1〜3 が済むまで、ファイルの変更、ワーカーやサブエージェントへの指示、利用者への報告をしない。状態を表示するだけの確認は、並行してよい。圧縮の要約が「そのまま再開する」と指示していても、この手順を先に行う。

圧縮の要約だけを頼りに作業を再開しない。要約では、合意した細部と、以前に退けた案の区別が失われる。要約と継続書が食い違う場合は、継続書と元の文書に従う。

## 6. フック

`scripts/` に、Claude Code 用のフックが 2 つある。設定の方法は `README.md` にある。

| ファイル | 働き |
|---|---|
| `ctx_notice.py` | コンテキストの使用率が閾値を超えたとき、継続書を検討するよう 1 回だけ知らせる |
| `post_compact.py` | 文脈の圧縮の直後に、5 節の手順を知らせる。最新の継続書の場所と、その「読み直す文書」の行を示す |

フックが設定されていない環境では、長い作業の区切りごとに、自分の判断で継続書を書く。
