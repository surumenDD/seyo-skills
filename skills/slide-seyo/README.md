# slide-seyo

AI エージェントに発表スライドを作成させるスキルです。見出しにはそのスライドの主張を書き、主張ごとに証拠の示し方を選びます。描画した結果は検査スクリプトで測定し、可読性の基準を満たすまで直します。既存のスライドの修正と点検にも使えます。

このファイルは人が読むための説明です。エージェントが読むのは `SKILL.md` です。

## 使い方

名前を出して頼みます。

```
/slide-seyo この README をもとに、ゼミ用に 5 枚で紹介スライドを作って
```

```
slide-seyo で、来月の学会発表（15 分）のスライドを作りたい。段階ごとに承認を待って進めて
```

```
/slide-seyo この deck.pdf を点検して
```

## 進み方

既定では、エージェントは作成の前に構成案を表で示し、利用者の返答を待ちます。構成案に書く項目は次のとおりです。

- 発表全体の主張の一文
- 聞き手・目的・形式
- スライドごとの見出し、証拠の示し方、＋−
- 依頼の言葉が複数の意味に取れた点と、その解釈

＋−は、そのスライドの事実が問題を示すか（−）、対処が有効であることを示すか（＋）の区別です。構成案は「前提が違う場合は指摘お願いします。なければ作成します。」で結びます。指摘がなければ、エージェントはスライドを作成して検査します。

依頼の仕方によって、進み方は次のように変わります。

| 依頼の仕方 | エージェントの進み方 |
|---|---|
| 指定なし | 構成案を示して返答を待つ。指摘がなければ作成する |
| 承認を待つよう指定する | 構成、話す内容、図の見本を順に確認し、承認のあとに作成する（`references/stages.md`） |
| 確認せずに作るよう指示する | 構成案を示し、返答を待たずに作成する。結びは「このまま作成します。」になる |
| 構成案は不要と伝える | 構成案を示さずに作成する |

利用者が書いた原稿と、決定や引き継ぎの文書は、利用者の承認を得てから変更します。

## 検査する項目

| 項目 | 既定 |
|---|---|
| 本文の文字サイズ | 18 pt 以上（高さ 7.5 in のスライドでの値） |
| 補足（出典、ページ番号）の文字サイズ | 12 pt 以上 |
| 文字と背景のコントラスト比 | 7:1 以上。大きい文字と補足は 4.5:1 以上 |
| スライドからのはみ出し、文字どうしの重なり | ない |
| 見出しの行数 | 2 行まで |

閾値は変更できます。エージェントが変更したときは、構成案と報告に理由を書きます。可読性の基準と検査スクリプトは自己テストと実際のデッキで動作を確かめてあります。

検査スクリプトが測定するのは、文字として描画された部分だけです。画像になっている図の中の文字、配置のバランス、図が主張を示しているかは、エージェントが描画した画像を見て確かめます。スライドの文言と発表原稿は書いた本人以外のエージェントにも点検させます。

## 対応している形式

| 形式 | 検査の方法 |
|---|---|
| HTML のスライド | ブラウザで描画して測定します（`scripts/check_html.mjs`） |
| .pptx、Keynote、Google スライド、LaTeX のスライド | PDF に書き出して、その PDF を測定します（`scripts/check_pdf.py`） |

Windows に PowerPoint があれば、エージェントは PowerPoint に .pptx を PDF として書き出させます。それ以外の環境では、使っているツールで PDF として保存し、エージェントに渡してください。

## 既定より優先する基準

次の基準があれば、エージェントはこのスキルの既定より優先します。複数あるときは、一覧の上にある基準を優先します。

- 利用者の指示
- プロジェクトの決まり（`CLAUDE.md`、`AGENTS.md`、`docs/` の下の決定や用語の文書、利用者が指定したファイル）
- 会場や所属のテンプレート
- 過去のデッキ

## 一緒に使うスキル

- 論述の層（ronjutsu-seyo）と文体の層（buntai-seyo）は構成と文言の基準を定めます。エージェントは構成案を書く前と、スライドの文言と発表原稿を書く前に読みます。文言の点検にも使います。二つの層が入っていない置き場では、`references/structure.md` にある最低限の規則で作成します。
- delegate-seyo は、別のエージェントに作業を委譲するときの手順を定めます。
- 調査のスキル imozuru（MaryCache/imozuru）は任意です。図の描き方に迷ったとき、同じ内容を扱った論文の図や講演のスライドを集めるのに使います。入っていなければ、エージェントは通常の検索で調べます。

## 依存パッケージのインストール

検査スクリプトを使うには、初回だけ準備が要ります。どちらも、このフォルダで実行します。

HTML の検査には、Node と、Chrome か Edge が要ります。

```
cd scripts
npm install
node check_html.mjs --selftest
```

PDF の検査には、Python 3.9 以上が要ります。

```
python -m venv scripts/.venv
scripts\.venv\Scripts\python -m pip install -r scripts/requirements.txt
scripts\.venv\Scripts\python scripts/check_pdf.py --selftest
```

上は Windows のパスです。macOS と Linux では `scripts\.venv\Scripts\python` を `scripts/.venv/bin/python` にします。

インストールしたパッケージはこのフォルダの `scripts/node_modules/` と `scripts/.venv/` に入ります。作者の環境では合計約 92 MB でした。パッケージはこのフォルダの中にあるので、スキルと一緒に消えます。

導入、一覧に名前だけを出す設定、削除の手順は[導入の手引き](../../docs/install.md)にあります。

## ファイルの構成

```
slide-seyo/
├─ SKILL.md                  エージェントが読む本体
├─ README.md                 このファイル
├─ references/
│  ├─ structure.md           構成の原則（スライドに固有のもの）
│  ├─ patterns.md            避けるデザインのパターンと、修正前後の例
│  ├─ wording-ja.md          文言と発表原稿（日本語。スライドに固有のもの）
│  ├─ wording-en.md          文言と発表原稿（英語。英語に固有のもの）
│  ├─ theme.md               デザインの設定値と、差し替え方
│  ├─ legibility.md          可読性の基準と、その理由
│  ├─ stages.md              段階ごとに承認を待つ場合の手順
│  ├─ backend-html.md        HTML で作成するとき
│  ├─ backend-pdf.md         .pptx など、PDF に書き出せる形式で作成するとき
│  └─ sources.md             根拠にした文献の一覧
└─ scripts/
   ├─ check_html.mjs         HTML の検査
   ├─ inpage_measure.js      ページの中で動く測定と判定
   ├─ package.json
   ├─ check_pdf.py           PDF の検査
   ├─ export_pdf.ps1         PowerPoint に PDF を書き出させる（Windows）
   └─ requirements.txt
```
