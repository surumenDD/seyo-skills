# PDF に書き出せる形式で作成する（.pptx、Keynote、Google スライド、LaTeX）

これらの形式では、作成したファイルそのものではなく、描画した結果の PDF を測定する。発表当日と同じツールで書き出した PDF を測定すれば、当日に表示されるものを測定したことになるからである。

## 1. 作成方法

.pptx を作成するためのスキルやライブラリが使える環境では、ファイルの作成はその作法に従い、このスキルの基準はその内容に適用する。

- 見出し、スライドの文言、発表原稿は 1 つの元のファイルに書き、そこからスライドを作成する（`stages.md` の 3）。スライド上で直接修正しない。
- 文字サイズと色は、テーマの値（`theme.md`）を 1 か所で定義して使う。
- 図はスライドに配置するサイズで作成し、配置したあとで拡大や縮小をしない。
- 見出しと、数行にわたる文言は、意味の切れ目で手動で改行する。
- 発表原稿は、発表者ノートに入れる。
- 文字を枠に収めるために、文字を自動で縮小する設定を使わない。縮小された文字は下限を下回るので、収まらなければ文言を減らすか、スライドを分ける。

## 2. PDF にする

PDF は発表当日に使うツールで書き出す。別のツールで変換すると、フォントの置き換えや折り返しの違いで、当日とは違うものを測定することになる。

| 環境 | 方法 |
|---|---|
| Windows で PowerPoint がある | 検査スクリプトに `--pptx` を渡すと、PowerPoint に書き出させてから測定する（`scripts/export_pdf.ps1` を使う。ファイルは読み取り専用で開き、上書き保存しない） |
| それ以外で PowerPoint、Keynote、Google スライドを使う | そのツールの「PDF として保存（書き出し）」で作成した PDF を渡す。エージェントが操作できない場合は、利用者に書き出しを依頼する |
| LaTeX | 組版した PDF をそのまま渡す |
| 当日のツールが使えず、別のツールで変換するしかない | 変換した PDF を測定する。報告に、どのツールで変換したかと、折り返しが当日と変わる可能性があることを書く。検査の出力にも、描画したツールの推定が出る |

利用者が同じ .pptx を PowerPoint で開いていると書き出しが止まるので、その場合はファイルを閉じてもらうか、利用者に PDF を書き出してもらう。

非表示のスライドは既定では書き出さず、含める場合は `--include-hidden` を付ける。

## 3. 検査

検査は `scripts/check_pdf.py` で行い、Python 3.9 以上と、`scripts/requirements.txt` のライブラリ（pypdfium2 と numpy）が必要である。

初回の準備（どちらか）

```
python -m venv scripts/.venv
scripts/.venv/bin/python -m pip install -r scripts/requirements.txt      （Windows は scripts\.venv\Scripts\python）
```

```
python -m pip install -r scripts/requirements.txt
```

`scripts/.venv` があれば、その中の python で実行する。

```
python scripts/check_pdf.py deck.pdf --shots shots
python scripts/check_pdf.py --pptx deck.pptx --pdf-out deck.pdf --shots shots
python scripts/check_pdf.py deck.pdf --appendix-from 15
python scripts/check_pdf.py --selftest
```

- `--shots` で、全ページの画像を保存する。`--json` で、すべての結果を保存する。`--verbose` で、参考情報をすべて出力する。
- `--pages 1-14,20` で、検査するページを絞る。
- `--appendix-from N` で、N ページ以降を付録として扱い、付録の下限（既定 14 pt）で測定する。予備のスライドに細かい表を載せるときに使う。
- 終了コードは、0 が違反 0 件、1 が違反あり、2 が実行できなかった場合である。

項目の意味（G1、G2、G3、G5、G6 と参考情報）は HTML の検査と同じで `backend-html.md` の 3 にあり、違う点は次のとおりである。

| 違い | 理由と対処 |
|---|---|
| テキストの枠からのオーバーフロー（G4）はない | PDF では、枠からオーバーフローした文字は切れずに描画されるので、オーバーフローは重なり（G5）、はみ出し（G3）、余白の逸脱（I1）として現れる |
| 補足かどうかを、位置で推定する | PDF には役割の情報がない。ページ下端の領域（既定は高さの下 10%）にある文字を補足として扱う。図の下の注記などが本文として測定され、コントラスト比の違反として出る場合は、`--footer-band 0.2` のように領域を広げるか、その注記を本文の基準まで濃くする |
| 見出しを、位置とサイズで推定する | 上端の領域にある、そのページで最も大きい文字のまとまりを、見出しとして数える。推定の確度が低いページは参考情報に出るので、画像で確認する |
| 上付き文字、下付き文字は参考情報に出る | 描画されたサイズが小さいためである。読ませる必要のある上付き文字なら、指定を上げる |
| 図の中の文字は測定できない（I6） | 画像がスライドの大きな割合を占めるページが一覧になる。図の中の文字は、図を作成する側で、配置するサイズで確認する |
| 行ごとに数える | 表の多いページでは件数が増える。件数ではなく、どのページのどの文字かを確認する |

誤検出が起きやすいのは、分数や積み上げた数式（重なりとして出る）と、写真の上の文字（「判定できない」として出る）であり、どちらも保存した画像で確認する。

## 4. 画像を確認する

検査で違反が 0 件になったら、`--shots` の画像を全ページ確認する（`patterns.md` の 4）。可能なら、別のエージェントに画像だけを渡して確認させる。

動画やアニメーションを使っている場合、PDF には最初のフレームが出力されるので、最初のフレームだけで意味が通じるかを確認する。

## 5. 検査を実行できないとき

PDF が手に入らない、Python やライブラリをインストールできない、という場合は、できる範囲まで進めて、残りを次の対応として報告する。

- PDF がない: 「PowerPoint で PDF として保存し、そのファイルを渡してもらえれば、文字サイズと重なりを測定できる」と書く。
- ライブラリをインストールできない: 何をインストールできなかったかと、インストールするためのコマンドを書く。

画像を確認するだけでは、文字が 18 pt あるか、コントラスト比が足りているかは判定できないので、検査を実行できていない間は、可読性の基準を確認したとは報告しない。
