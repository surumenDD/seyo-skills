# 構成の原則

発表の構成について、スライドという形に固有の既定とその理由をまとめた。何をどの順で主張するか、事実にどういう意味を添えるか、問題をどう定義するか、結論に何を置くかは論述の層（ronjutsu-seyo）の「発表（スライドと台本）」の項が扱い、用語と指示語は文体の層（buntai-seyo）が扱うので、ここでは繰り返さない。どの項目も、理由は聞き手がどこで迷うかにある。発表の種類に合わない項目は理由に照らして変更し、何をなぜ変えたかを構成案に書く。

項目ごとに、根拠の種類を記号で示した。文献は `sources.md` にある。

| 記号 | 根拠 |
|---|---|
| ［複］ | 複数の文献が一致している |
| ［単］ | 文献が 1 つ |
| ［割］ | 文献どうしで意見が分かれている |
| ［経］ | 過去の研究発表 1 件を作成したときに発表者から受けた指摘に基づく。文献の裏づけはない |

［経］の項目は 1 件の発表から得たものなので、当てはまるかどうかは、その項目の理由が今回の発表でも成り立つかで判断する。

## 1. 発表の役割と積み上げ方

スライド 1 枚は、発表が聞き手に積み上げる価値の 1 段に当たり、見出しがその段の主張、図や表がその証拠である。発表原稿では、証拠の読み方と、その段が主張にとって何を意味するかを話す。

積み上げ方は発表の種類で変わる。研究発表は、論述の層の「発表（スライドと台本）」の項の順（先行研究の問題、そこから生じる研究の問い、対処、問いへの答えとしての結果、貢献）に従う。研究発表以外の既定は次のとおりである。

| 発表の種類 | 積み上げ方 |
|---|---|
| ツールや手順の紹介 | 何ができるようになるか → 導入 → 使い方 → 結論 |
| 進捗や結果の報告 | 目的 → 分かったこと → それで何が決まるか → 次の対応 |

ツールや手順の紹介では、聞き手がいま困っていることが研究発表の問題に当たる。それを先に述べると、ツールの紹介が聞き手にとっての価値になる。

## 2. 見出し

- 見出しには、そのスライドの主張を、主語と述語のある一文で書く。題目だけの見出し（「実験結果」「導入方法」）では、聞き手が図から主張を自分で探すことになる。［複］
- 2 行以内に収める。収まらないときは、文字を小さくする前に文言を短くする。［複］
- 見出しを順に読んだときに発表の要約になっているかを、構成案の段階で確認する。［単］
- 同じ見出しを 2 枚のスライドに使わない。［複］

実例として、2026-11-13 に作成した、ツールの導入を紹介するデッキの見出しを示す。初版は、デザインと日本語の両方についてユーザーから作り直しを求められた。

| 初版 | 修正後 |
|---|---|
| 調べる道具と、試す道具 | Claude Code と Codex は alphaXiv MCP で論文を調べ、OpenResearch の orx で実験を実行できる |
| サーバーを一つ登録して、認証する | alphaXiv MCP は mcp add コマンドで登録でき、Claude Code ではブラウザで、Codex では API キーで認証する |
| 会話の中で論文を調べる | alphaXiv MCP を使うと、論文の検索から実装の閲覧までをエージェントとの会話の中で行える |
| 調べて、試して、結果でまた調べる | 結論: Claude Code と Codex は alphaXiv MCP で論文を調べ、orx で実験を実行できる |

初版の見出しはどれも題目か標語で、主語がないため、何がどうなるのかを聞き手が読み取れなかった。見出しに漠然とした語や比喩を置かない理由は、文体の層の第 1 節にある。

## 3. スライド 1 枚の構成と、証拠の示し方

- 1 枚のスライドに、主張を 1 つと、それを支える証拠を 1 つ置く。［複］
- 1 枚にかける時間は 1 分以内を目安にし、それを超える内容は次のスライドか付録に移す。枚数は制限せず、数十秒のスライドが多数あってよい。［複］
- スライドの文は短い句にする。箇条書きは 1 項目 2 行まで、1 つの箇条書きは 4 項目までを目安にする。［複］
- 文字だけのスライドは、文字そのものが主張である場合（問いを立てるスライドなど）に限る。［複］
- 内容と関係のない画像や装飾を入れない。［複］
- 補足を主役より目立たせない。補足が位置で目立つ（端に飛び出す、主役と横に並ぶ）と、聞き手はどれが主役か分からなくなる。［経］

スライドの文字と発表原稿をどこまで対応させるか、内容を詰め込みすぎたスライドをどう分けるかは、論述の層の「発表（スライドと台本）」の項にある。

### 証拠の示し方を主張から選ぶ

手元の材料から作成すると、どのスライドも同じ形になる。主張が何を述べているかを見て、それを最も直接に示せる形式を選ぶ。

| 主張が述べていること | 向く形式 | 向かない形式 |
|---|---|---|
| A と B がどうつながるか、何が何を経由するか | 箱と矢印の図 | 箇条書き |
| 項目ごとに何が対応するか | 表、行の並び | 段落の文章 |
| 量の大小、増減、ばらつき | グラフ（線の端にラベルを付ける） | 数値の表 |
| 手順、入力するコマンド | コマンドそのもの、実際の画面 | 手順の説明文 |
| 聞き手が知らない物がどういう物か | 実物の画像、短い動画 | 言葉での説明 |
| 式のどの部分が重要か | 式を 1 つと、注目する部分の印 | 式の羅列 |
| 前後で何が変わったか | 同じ配置の 2 枚（変わる部分以外は動かさない） | 1 枚に両方を詰める |
| 問い、結論の一文 | 大きな文字の一文 | 小さい文字の段落 |

作成し終えたら各スライドの主な形式を並べ、同じ形式が続く区間では、スライドごとに、その主張を最も直接に示せる形式を検討し直す。問題になるのは主張が違うのに形式が同じ場合であり、形式を変えること自体は目的ではないので、証拠を並べる区間で同じ形式のグラフが続くのは自然である。2026-11-13 のデッキでは、修正後も 7 枚中 5 枚が「見出しと、文字の表」になった。これはユーザーの指摘ではなく、作成後に気づいた点である。

### 複雑な図

複雑な図は、要素を 1 つずつ追加しながら数枚に分ける。前後のスライドで共通する要素は位置を変えない。少しでも動くと、聞き手は動いた箇所に意味を探すからである。［複］

格子状に並べる部品は位置を揃える。わずかなずれは、乱れか、意味のある差に見える。［経］

## 4. スライドのつなぎと、例の出し方

各スライドの事実に意味（問題を示すのか、対処が効くことを示すのか）を添えること、次のスライドへ渡す問いをそのスライドの内容から導くこと、前のスライドが渡した問いを次のスライドの見出しか冒頭で受けることは、論述の層の 3.1、3.2 と「発表（スライドと台本）」の項にある。スライドの構成として加えるのは、渡したい内容がそのスライドに表示されていなければ、論理が飛躍しているのでスライドを追加する、という対処である。［経］

例はまとめて出す。1 つだけ挙げて、あとで別の例を追加すると、聞き手は同じ話を 2 度聞くことになる。［経］

## 5. 用語と、言い方の範囲

用語を元の資料と同じ語にそろえること、平易にするときも用語を言い換えずに説明を添えること、同じものを 2 通りに呼ばないこと、指示語の指す先を聞き手が決められるようにすることは文体の層の第 1 節と「発表（スライドと台本）」の項に、あとで使わない語を定義しないことは論述の層の 3.3 にある。

すべてに当てはまるような言い方をしない。「X は Y する仕組みである」ではなく、「この発表で扱うのは、Y する X である」と書く。当てはまらない例を知っている聞き手は、そこで発表への信頼を下げる。［経］

## 6. 結論、最後のスライド、予備のスライド

結論に新しい事実を置かないことは、論述の層の「発表（スライドと台本）」の項にある。スライドでは、それまでに示した内容を、それまでのスライドに表示した内容に限り、発表原稿で話しただけの内容は含めない。新しい事実が必要なら、本編にスライドを追加する。［経］

- 最後のスライドを、お礼の言葉だけにしない。結論を載せ、質疑の間も表示しておく。［複］
- 予備のスライドは結論のあとに置く。数が多い場合は目次のスライドを 1 枚作り、各スライドと行き来できるようにする。［複］

## 7. 限界と、主張を弱める結果の置き場所

AI は、限界や試していないことを隠さずに書こうとして、スライドや発表原稿に否定の文を重ねやすい。限界をどこにどう書くか、主張を弱める結果をどう扱うか、作業の事情をどこに書くかは、論述の層の 3.4 と 3.8 に従う。発表では論文の付録に当たる場所が予備のスライドであり、主張を弱める結果は、本編で数や範囲を正確に述べ（「5 課題中 4 課題で」）、詳細を予備のスライドに置いて質疑で答える。

元の資料の言い回しを、そのまま写さない。論文や報告書には、断定を弱めた文（「〜しうる」「条件によっては改善が見られる」）が残っていることがあり、発表では、根拠が及ぶ範囲を主語や修飾に入れたうえで言い切る。言い切りを弱めるかどうかは内容の判断なので、迷ったらユーザーに尋ねる。［経］

## 8. 出典と脚注

- 出典は、他人の主張、画像、理論、指標が出るスライドにだけ置き、自分の手続きや結果のスライドには置かない。［複］
- 位置、文字サイズ、書式を全スライドで統一する。既定は左下で、ページ番号と同じ行に置く。［単］
- 書式は「名前 (第一著者 et al., 年)」とする。複数ある場合は「; 」で区切ってスライドに出る順に並べ、会議名、誌名、題名は書かない。［割］題名も書く流儀があるので、発表する場の慣例があればそれに合わせる。
- Web の文書は「URL (組織, 年)」とする。
- 同じ出典を、連続するスライドで繰り返さない。［経］
- 発表全体が 1 つの資料（紹介するツールの説明書、元の論文など）に基づく場合は、その資料の出典を、内容が最初に出るスライドに 1 度だけ置く。
- 公開されていない資料や手元の文書は「文書の名前 (作成者, 年)」と書き、聞き手がたどれない場所（手元のファイルのパスなど）は書かない。
- 番号だけの引用（[17]）は、聞き手には伝わらない。［単］
- 脚注の位置は出典の場所なので、そこに補足の説明を並べない。補足が必要なら、本文の中に、主役より目立たない形で置く。［経］

書式は 1 枚ずつ決めず、最初に 1 つ決めて全スライドに適用する。スライドごとに決めると、必ず不統一になる。

## 9. 図、表、式、コード

図

- 凡例を離して置かず、線の端や棒の近くにラベルを直接付ける。［複］
- 図は、スライドに配置するサイズで作成する。あとから拡大や縮小をすると、図の中の文字サイズが変わる。［経］
- 論文の図は文字が小さすぎることが多いので、発表用に作り直す。［単］
- 線は太くし（3 pt 前後）、縦軸のラベルは回転させず横書きにする。［単］
- 起きていないことを、実物の画像で起きたように見せない。一般論は模式図で描き、模式図だと分かるようにする。［経］
- 図の描き方に迷ったら、imozuru で同じ内容を扱った論文の図や講演のスライドを集め、その慣例に従う。［経］

表

- 論文の表を画像のまま貼らず、発表で見せる列と行だけを選んで作り直す。［複］
- 値は元のデータから読み込み、手入力しない。
- 罫線は少なくし、強調は主張に関係する箇所だけにする。

式

- 式は 1 枚に 1 つ、新しい記号は 7 個までを目安にする。［単］
- スライドに出る記号は、そのスライドか前のスライドで定義する。［経］
- 式の細部は元の資料に任せ、発表では言葉と図で説明する。論文の式の説明を、そのまま発表原稿に持ち込まない。［複］

コード、コマンド（2026-11-13 のデッキ 1 件での経験に基づく試案）

- 等幅フォントを使い、途中で折り返さない。長いコマンドは、行継続の記号を使って意味の切れ目で分ける。
- 聞き手がそのまま入力できる形で載せ、途中を省略した、実行できない形にしない。

## 10. 文献で意見が分かれている点

次の点は文献どうしで意見が分かれており、既定を 1 つ決めてあるが、発表する場の慣例やユーザーの希望があればそちらに合わせる。

| 論点 | 既定 | 別の立場 |
|---|---|---|
| 目次のスライド | 置かない。短い発表では、内容を述べないまま時間を使う | 長い発表や講義では置く方がよいとする文献がある |
| 貢献を述べる位置 | 結論で述べる | 冒頭で述べる、両方で述べる、とする文献がある |
| 結論を先に述べるか、積み上げるか | 積み上げて最後に述べる | 先に述べることを勧める文献の方が多い。聞き手が忙しい報告では、先に述べる |
| 背景の明暗 | 明るい背景に濃い文字。投影での読みやすさを測定した研究がこちらを支持する | 暗い背景を勧める意見もある |
| 箇条書き | 短い句で、4 項目まで | 箇条書きそのものを避けるとする文献がある |
| 1 項目ずつ表示するアニメーション | 複雑な図は、スライドを分けて積み上げる。アニメーションは使わない | 1 項目ずつ表示しないことを欠点とする調査がある |
| 文字サイズの下限 | 18 pt | 20 pt 超、24 pt、会場の広さで決める、とする文献がある。広い会場では上げる |

## 11. 過去の研究発表での個別の判断

次の判断は、過去の研究発表 1 件で、その発表の事情に合わせて決めたものであり、既定ではない。似た場面では、同じ事情が今回の発表にも当てはまるかで判断する。

| 判断 | 事情 |
|---|---|
| 結論を、研究の問いと「はい」の形ではなく平叙文で述べ、続けて貢献を 3 点並べた | 13 分の発表を 10 分に縮める版での変更。その前の版では、研究の問いを読み上げて答える形を採っていた |
| 結論のスライドの見出しを「結論: …」で始めた | 上と同じ版での変更 |
| 例外の課題を、発表原稿では名前を挙げて説明しなかった | スライドで「5 課題中 4 課題」と数で述べたうえでの判断で、発表者もこの点について意見を求めていた |
| 研究の問いを 1 つ立て、4 つの小さな問いで検証し、結論で問いに戻った | その研究の構成に合わせたもの |
