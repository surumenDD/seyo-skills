# 構成の原則

発表の構成について、スライドという形に固有の既定とその理由をまとめた。何をどの順で主張するかは論述の層（ronjutsu-seyo）が、用語と指示語は文体の層（buntai-seyo）が扱う。ただし層が入っていない環境でも使えるよう、スライドで欠かせない規則はここにも短く書き、詳しい箇所を添えた。どの項目も、理由は聞き手がどこで迷うかにある。発表の種類に合わない項目は理由に照らして変更し、何をなぜ変えたかを構成案に書く。

項目ごとに、根拠の種類を記号で示した。文献は `sources.md` にある。

| 記号 | 根拠 |
|---|---|
| ［複］ | 複数の文献が一致している |
| ［単］ | 文献が 1 つ |
| ［割］ | 文献どうしで意見が分かれている |
| ［経］ | 過去の発表を作成したときに、発表者から受けた指摘に基づく。文献の裏づけはない |

［経］の項目は少数の発表から得たものである。その項目の理由が今回の発表でも成り立つかで、当てはまるかを判断する。

## 1. 発表の役割と積み上げ方

スライド 1 枚は、発表が聞き手に積み上げる価値の 1 段にあたる。見出しがその段の主張で、図や表がその証拠である。発表原稿では、証拠の読み方と、その段が主張にとって何を意味するかを話す。

積み上げ方は発表の種類で変わる。研究発表は、先行研究の問題、そこから生じる研究の問い、対処、問いへの答えとしての結果、貢献の順に進める（論述の層の「発表（スライドと台本）」の項）。研究発表以外の既定は次のとおりである。

| 発表の種類 | 積み上げ方 |
|---|---|
| ツールや手順の紹介 | 何ができるようになるか → 導入 → 使い方 → 結論 |
| 進捗や結果の報告 | 目的 → 分かったこと → それで何が決まるか → 次の対応 |

ツールや手順の紹介では、聞き手がいま困っている点が、研究発表の問題にあたる。それを先に述べると、ツールの紹介が聞き手にとっての価値になる。

## 2. 見出し

- 見出しにはそのスライドの主張を、主語と述語のある一文で書く。題目だけの見出し（「実験結果」「導入方法」）では、聞き手は図から主張を自分で探さなければならない。［複］
- 2 行以内に収める。収まらないときは、文字を小さくする前に文言を短くする。［複］
- 見出しを順に読んだときに発表の要約になっているかを、構成案の段階で確かめる。［単］
- 同じ見出しを 2 枚のスライドに使わない。［複］

題目の見出しを、主張の一文に直した例を示す。ツールの導入を紹介するデッキの見出しである。

| 初版 | 修正後 |
|---|---|
| 調べる道具と、試す道具 | Claude Code と Codex は alphaXiv MCP で論文を調べ、OpenResearch の orx で実験を実行できる |
| サーバーを一つ登録して、認証する | alphaXiv MCP は mcp add コマンドで登録でき、Claude Code ではブラウザで、Codex では API キーで認証する |
| 会話の中で論文を調べる | alphaXiv MCP を使うと、論文の検索から実装の閲覧までをエージェントとの会話の中で行える |
| 調べて、試して、結果でまた調べる | 結論: Claude Code と Codex は alphaXiv MCP で論文を調べ、orx で実験を実行できる |

初版の見出しはどれも題目か標語で、主語がない。そのため、何がどうなるのかを聞き手が読み取れなかった。見出しには漠然とした語や比喩も置かない（文体の層の第 1 節）。

## 3. スライド 1 枚の構成と、証拠の示し方

- 1 枚のスライドに、主張を 1 つと、それを支える証拠を 1 つ置く。［複］
- 1 枚にかける時間は 1 分以内を目安にする。超える内容は次のスライドか付録に移す。枚数は制限せず、数十秒のスライドが多数あってよい。［複］
- スライドの文は短い句にする。箇条書きは 1 項目 2 行まで、1 つの箇条書きは 4 項目までを目安にする。［複］
- 文字だけのスライドは、文字そのものが主張である場合（問いを立てるスライドなど）に限る。［複］
- 内容と関係のない画像や装飾を入れない。［複］
- 補足を主役より目立たせない。補足が位置で目立つ（端に飛び出す、主役と横に並ぶ）と、聞き手はどれが主役か分からなくなる。［経］

スライドと発表原稿は次のように対応させる。詳しくは論述の層の「発表（スライドと台本）」の項にある。

- 発表原稿の最初の文は、見出しと同じ主語・同じ内容にする。
- 発表原稿で触れない図表は載せない。
- 詰めすぎたスライドは分ける。短いスライドが多くてよい。

### 証拠の示し方を主張から選ぶ

手元の材料から作成すると、どのスライドも同じ形になる。主張が何を述べているかを見て、それを最も直接に示せる形式を選ぶ。

| 主張が述べていること | 向く形式 | 向かない形式 |
|---|---|---|
| A と B がどうつながるか、何が何を経由するか | 箱と矢印の図 | 箇条書き |
| 項目ごとに何が対応するか | 表、行の並び | 段落の文章 |
| 量の大小、増減、ばらつき | グラフ（線の端にラベルを付ける） | 数値の表 |
| 手順、入力するコマンド | コマンドそのもの、実際の画面 | 手順の説明文 |
| 聞き手が知らない物がどういう物か | 実物の画像、短い動画 | 言葉での説明 |
| 式のどの部分が重要か | 式を 1 つと、注目する部分の印 | 式の羅列 |
| 前後で何が変わったか | 同じ配置の 2 枚（変わる部分以外は動かさない） | 1 枚に両方を詰める |
| 問い、結論の一文 | 大きな文字の一文 | 小さい文字の段落 |

作成し終えたら、各スライドの主な形式を並べる。同じ形式が続く区間では、スライドごとに、その主張を最も直接に示せる形式を検討し直す。問題になるのは、主張が違うのに形式が同じ場合である。形式を変えること自体は目的ではないので、証拠を並べる区間で同じ形式のグラフが続くのは自然である。

### 複雑な図

複雑な図は要素を 1 つずつ追加しながら数枚に分ける。前後のスライドで共通する要素は位置を変えない。少しでも動くと、聞き手は動いた箇所に意味を探すからである。［複］

格子状に並べる部品は位置をそろえる。わずかなずれは、乱れか、意味のある差に見える。［経］

## 4. スライドのつなぎと、例の出し方

スライドの間は次のようにつなぐ。詳しくは論述の層の 3.1・3.2 と「発表（スライドと台本）」の項にある。

- 各スライドの事実には、それが問題を示すのか、対処が有効であることを示すのかという意味を添える。
- 次のスライドで扱う問いは、そのスライドの内容から導く。
- 前のスライドで示した問いは、次のスライドの見出しか冒頭で受ける。
- 次のスライドの前提にする内容がそのスライドに表示されていなければ、論理が飛躍している。そのときはスライドを追加する。［経］
- 例はまとめて出す。1 つだけ挙げてあとで別の例を足すと、聞き手は同じ話を 2 度聞くことになる。［経］

## 5. 用語と、言い方の範囲

用語と言い方は次のようにそろえる。詳しくは文体の層の第 1 節と「発表（スライドと台本）」の項、論述の層の 3.3 にある。

- 用語は元の資料と同じ語にそろえる。平易にするときも語は変えず、説明を添える。
- 同じ対象を二通りの名前で呼ばない。
- 指示語は、指す先を聞き手が一つに決められるときだけ使う。
- あとで使わない語を定義しない。
- すべてに当てはまるような言い方をしない。「X は Y する仕組みである」ではなく、「この発表で扱うのは、Y する X である」と書く。当てはまらない例を知っている聞き手は、そこで発表への信頼を下げる。［経］

## 6. 結論、最後のスライド、予備のスライド

- 結論に新しい事実を置かない。結論のスライドに載せるのは、それまでのスライドに表示した内容に限り、発表原稿で話しただけの内容は含めない。新しい事実が必要なら、本編にスライドを追加する。［経］
- 最後のスライドを、お礼の言葉だけにしない。結論を載せ、質疑の間も表示しておく。［複］
- 予備のスライドは結論のあとに置く。数が多い場合は目次のスライドを 1 枚作り、各スライドと行き来できるようにする。［複］

## 7. 限界と、主張を弱める結果の置き場所

AI は、限界や試していないことを隠さずに書こうとして、スライドや発表原稿に否定の文を重ねやすい。次のように扱う。詳しくは論述の層の 3.4 と 3.8 にある。

- 主張の範囲を変える限界や不利な結果は、本編で一度、数や範囲を正確に述べる（例：「10 件中 8 件で」）。
- 詳細は予備のスライドに置き、質疑で答える。発表では、予備のスライドが論文の付録にあたる。
- 主張を変えない断り書きは、スライドにも発表原稿にも置かない。
- 元の資料の言い回しを、そのまま写さない。論文や報告書には、断定を弱めた文（「〜しうる」「条件によっては改善が見られる」）が残っていることがある。発表では、根拠が及ぶ範囲を主語や修飾に入れたうえで言い切る。言い切りを弱めるかどうかは内容の判断なので、迷ったら利用者に尋ねる。［経］

## 8. 出典と脚注

- 出典は他人の主張、画像、理論、指標が出るスライドにだけ置き、自分の手続きや結果のスライドには置かない。［複］
- 位置、文字サイズ、書式を全スライドで統一する。既定は左下で、ページ番号と同じ行に置く。［単］
- 書式は「名前 (第一著者 et al., 年)」とする。複数ある場合は「; 」で区切ってスライドに出る順に並べ、会議名、誌名、題名は書かない。［割］題名も書く流儀があるので、発表する場の慣例があればそれに合わせる。
- Web の文書は「URL (組織, 年)」とする。
- 同じ出典を、連続するスライドで繰り返さない。［経］
- 発表全体が 1 つの資料（紹介するツールの説明書、元の論文など）に基づく場合は、その資料の出典を、内容が最初に出るスライドに 1 度だけ置く。
- 公開されていない資料や手元の文書は「文書の名前 (作成者, 年)」と書く。聞き手がたどれない場所（手元のファイルのパスなど）は書かない。
- 番号だけの引用（[17]）は聞き手に伝わらない。［単］
- 脚注の位置は出典の場所なので、そこに補足の説明を並べない。補足が必要なら、本文の中に、主役より目立たない形で置く。［経］

書式は 1 枚ずつ決めず、最初に 1 つ決めて全スライドに適用する。スライドごとに決めると、必ず不統一になる。

## 9. 図、表、式、コード

図

- 凡例を離して置かず、線の端や棒の近くにラベルを直接付ける。［複］
- 図はスライドに配置するサイズで作成する。あとから拡大や縮小をすると、図の中の文字サイズが変わる。［経］
- 論文の図は文字が小さすぎることが多いので、発表用に作り直す。［単］
- 線は太くし（3 pt 前後）、縦軸のラベルは回転させず横書きにする。［単］
- 起きていないことを、実物の画像で起きたように見せない。一般論は模式図で描き、模式図だと分かるようにする。［経］
- 図は、図だけで伝わるかを確かめる。伝わらないときは、文字を書き足さずに図そのものを改める。［経］
- 図の描き方に迷ったら、同じ内容を扱った論文の図や講演のスライドを集め、その慣例に従う。調査のスキル（imozuru など）があれば使う。［経］

表

- 論文の表を画像のまま貼らず、発表で見せる列と行だけを選んで作り直す。［複］
- 値は元のデータから読み込み、手入力しない。
- 罫線は少なくし、強調は主張に関係する箇所だけにする。

式

- 式は 1 枚に 1 つ、新しい記号は 7 個までを目安にする。［単］
- スライドに出る記号は、そのスライドか前のスライドで定義する。［経］
- 式の細部は元の資料に任せ、発表では言葉と図で説明する。論文の式の説明を、そのまま発表原稿に持ち込まない。［複］

コード、コマンド

- 等幅フォントを使い、途中で折り返さない。長いコマンドは、行継続の記号を使って意味の切れ目で分ける。［経］
- 聞き手がそのまま入力できる形で載せ、途中を省略した、実行できない形にしない。［経］

## 10. 文献で意見が分かれている点

次の点は文献どうしで意見が分かれており、既定を 1 つ決めてある。発表する場の慣例や利用者の希望があれば、そちらに合わせる。

| 論点 | 既定 | 別の立場 |
|---|---|---|
| 目次のスライド | 置かない。短い発表では、内容を述べないまま時間を使う | 長い発表や講義では置く方がよいとする文献がある |
| 貢献を述べる位置 | 結論で述べる | 冒頭で述べる、両方で述べる、とする文献がある |
| 結論を先に述べるか、積み上げるか | 積み上げて最後に述べる | 先に述べることを勧める文献の方が多い。聞き手が忙しい報告では、先に述べる |
| 背景の明暗 | 明るい背景に濃い文字。投影での読みやすさを測定した研究がこちらを支持する | 暗い背景を勧める意見もある |
| 箇条書き | 短い句で、4 項目まで | 箇条書きそのものを避けるとする文献がある |
| 1 項目ずつ表示するアニメーション | 複雑な図は、スライドを分けて積み上げる。アニメーションは使わない | 1 項目ずつ表示しないことを欠点とする調査がある |
| 文字サイズの下限 | 18 pt | 20 pt 超、24 pt、会場の広さで決める、とする文献がある。広い会場では上げる |
