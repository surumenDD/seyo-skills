# HTML で作成する

ブラウザで表示する HTML のスライドの作成方法と、検査の手順をまとめた。

スライド用の仕組み（スライドを作成するための専用の機能、Marp、reveal.js など）が使える環境では、スライドの区切り方やファイルの配置はその仕組みの作法に従い、このスキルの基準はその内容に適用する。

## 1. 作成方法

- スライド 1 枚を 1 つの要素（既定は `section`）にし、スライドのサイズは 1920 × 1080 px を既定とする（`theme.md`）。
- 色、文字サイズ、余白の値は共通のスタイルの冒頭にまとめ、スライドごとに値を書かない。
- 見出しは `h2`（表紙は `h1`）にする。検査スクリプトは、既定で `h1` と `h2` を見出しとして行数を数える。
- 出典とページ番号は、役割が分かるようにする。検査スクリプトは既定で `.src`、`.pg`、`data-role="footnote"`、`data-role="page"` を補足として扱い、別の名前を使う場合は引数で指定する。
- 発表原稿は、各スライドの `aside` に書く。検査スクリプトは `aside` を測定しない。
- 見出しと、数行にわたるスライドの文言は、`<br>` で手動で改行する。
- コードとコマンドは等幅フォントにして、折り返さない（`white-space: nowrap`）。右の余白を越えやすいので、長いものは行継続の記号で分ける。

## 2. 起きやすい問題

| 問題 | 対処 |
|---|---|
| Web フォントが読み込まれず、代替のフォントで表示されて折り返しが変わる | 検査の出力の「フォント」の行を確認する。読み込めていなければ、フォントの指定か接続を修正してから、測定し直す |
| 見出しが 1 行のスライドと 2 行のスライドで、本文の開始位置がずれる | 見出しの高さを 2 行分に固定する |
| 絶対配置した出典やページ番号の位置が、スライドによって違う | 位置を共通のスタイルで決める。位置の不揃いは、検査の参考情報に出る |
| 画像にした図の中の文字は、検査スクリプトで測定できない | 図を、配置するサイズで作成する。そのサイズで 18 pt 以上になる文字サイズを指定する |
| 写真やグラデーションの上の文字は、コントラスト比を判定できない | 文字の後ろに無地の領域を敷く。検査スクリプトは「判定できない」として別に出力するので、画像で確認する |
| 上付き文字、下付き文字が小さくなる | 検査スクリプトは、描画されたサイズで測定する。下限を下回ったら、書き方を変えるか、指定を上げる |
| 公開先で表示が変わる（公開の仕組みが独自の変換をする場合） | 検査のあと、公開した実物を開いて、全スライドを確認する |

## 3. 検査

検査は `scripts/check_html.mjs` で行い、Node と、Chrome か Edge が必要である。初回だけ、`scripts` のフォルダで `npm install` を実行する（`playwright-core` がインストールされ、ブラウザ本体は新しくダウンロードしない）。

```
node scripts/check_html.mjs --html deck.html --shots shots
node scripts/check_html.mjs --deck <フォルダ> --shots shots --pdf deck.pdf
node scripts/check_html.mjs --selftest
```

- `--html` は、1 つの HTML ファイルを検査する。スライドの要素は `--slide-selector` で指定する（既定は `section`）。
- `--deck` は、スライドごとにファイルが分かれた構成（`project/deck.json` の `order`、`project/deck.css`、`project/slides/<id>.html`）を検査する。
- `--shots` で、全スライドの画像を保存する。`--pdf` で、1 枚 1 ページの PDF を保存する。
- `--json` で、すべての結果を保存する。`--verbose` で、参考情報をすべて出力する。
- 終了コードは、0 が違反 0 件、1 が違反あり、2 が実行できなかった場合である。

閾値と、見出しや補足の要素の指定は引数で変更でき（`--help`）、閾値を変更したら構成案と報告に書く（`legibility.md` の 2）。

### 出力の読み方

```
違反 5 件（G1 文字の大きさ 2、G2 コントラスト比 3）／判定できない 0 件／警告 0 件／参考 2 件
[1] s1 違反 5
  G1 p.text「Search papers, read …」 15 pt < 18 pt → font-size を 36px 以上に（今 30px）
  G2 p.source「Source: example.org/…」 2.81:1 < 4.5:1 → 文字色 #8A949C を背景 #F6F4EF からもっと離す
```

| 項目 | 意味 | 修正方法 |
|---|---|---|
| G1 | 文字が小さい | 文言を減らすか、スライドを分ける。文字だけを大きくして、枠からあふれさせない |
| G2 | 文字と背景のコントラスト比が足りない | 文字の色を濃くする。識別の色の文字なら、大きい太字にするか、本文の色にして色見本を添える |
| G3 | スライドからはみ出している | 配置し直す |
| G4 | 文字がテキストの枠からオーバーフローして切れている | 文言を減らす、枠を広げる、スライドを分ける |
| G5 | 文字どうしが重なっている | 配置し直す |
| G6 | 見出しが 3 行以上ある | 見出しの文言を短くする |

参考情報（I1〜I5）は違反ではなく、画像を確認するときの手がかりにする。

- I1: 余白の外に出ている内容と、出典とページ番号の位置の不揃い。余白は、左右を `--margin-in`（既定 0.6 in）、上下を `--margin-v-in`（既定 0.4 in）で判定する。
- I2: `<br>` の数と一致しない行数、最後の行が短い要素、右端までの余りが少ない行。手動で改行する設計のときに意図しない折り返しを見つけるためのもので、段落を自動で折り返す設計なら気にしなくてよい。
- I3: 各スライドの内容の外接矩形と、上下左右の空き。片側だけの大きな空きを見つけるために使う。
- I4: 使われている文字色の一覧。意図しない色が混ざっていないかを確認する。
- I5: 各スライドの構成の大まかな分類（figure、diagram、code、rows、text、mixed）の並び。主張が違うのに同じ分類が続いていたら、`structure.md` の 3 に戻って、証拠の示し方を選び直せないかを検討する。

### Node やブラウザの自動操作が使えない環境

`scripts/inpage_measure.js` は、ブラウザのページの中で動く 1 つの式である。ページ内で JavaScript を実行できるツールがあれば、スライドを開いたタブでこのファイルの内容を実行して同じ結果を得られ、使い方はファイルの冒頭に書いてある。

どちらも使えない場合は、検査を実行できていないことと、実行するために必要なもの（Node と Chrome、またはページ内で JavaScript を実行できるツール）を報告に書く。

## 4. 画像を確認する

検査で違反が 0 件になったら、`--shots` の画像を全スライド確認する（`patterns.md` の 4）。可能なら、別のエージェントに画像だけを渡して確認させる。

公開や発表に使う場所（公開先のページ、発表に使うブラウザ）で開いた実物も、手元の描画と変わることがあるので、全スライド確認する。
