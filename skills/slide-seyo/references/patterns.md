# デザイン: 避けるパターンと、修正前後の例

作成する前に 1 と 2 を読み、画像を確認して修正するときに 3 と 4 を使う。

目次

1. モデルが既定で作りやすいデザイン
2. 装飾についての考え方
3. 修正前後の例

---

## 1. モデルが既定で作りやすいデザイン

デザインの指定がないと、モデルは決まったパターンになりやすい。「AI らしさを避ける」と考えるだけでは、別の既定のパターンに入れ替わる。そのためパターンを名前で把握し、作成したあとに自分の出力に含まれていないかを確かめる。

| パターン | 発表に合わない理由 | 代わりに使うもの |
|---|---|---|
| 淡いクリーム色や生成りの背景 | 投影すると白く飛び、文字とのコントラストが下がる。意図のない色が背景に付く | 白に近い無彩色の背景 |
| 見出しの上の、小さな色つきのラベル（「導入」「活用」など） | 小さくて後ろの席から読めない。見出しに主張が書いてあれば不要である | 置かない。主張は見出しの文で述べる |
| 同じ形のカードを横に並べる | 内容どうしの関係（順序、対比、包含）が形に表れない。どのスライドも同じに見える | 関係を表す形式（矢印でつないだ図、表、行の並び） |
| 角丸の箱、影、箱の全面の塗りつぶし | 情報を持たない。塗りつぶしの上の文字は読みにくい | 囲みが必要なら、細い枠線か、ごく淡い塗り |
| 見出しの下の線、幅いっぱいの色の帯、端の縦線 | 情報を持たない装飾で、主張と証拠の領域を狭める | 置かない |
| グラデーション、絵文字、装飾のアイコン | 同上 | 置かない |
| 小さい灰色の説明文 | 後ろの席からは読めず、投影では白飛びで消える | 濃い文字。説明は本文より 1 段階だけ薄い色にとどめる |
| 等幅フォントのラベル、番号つきの節のラベル（01／02／03） | 装飾として使われることが多く、内容を持たない | 等幅フォントはコードとコマンドにだけ使う |
| 見出しの中の、斜体や色を変えた強調語 | 見出しは一文で主張を述べる場所で、1 語だけを飾る場所ではない | 強調したいことは、文の内容で述べる |
| 濃い色の背景の「締めの 1 枚」 | 1 枚だけ雰囲気が変わり、聞き手はそこに意味を探す | 全スライドを同じ背景にする |
| 中央揃えの本文 | 行の始まりが揃わず、読みにくい | 左揃え。中央に置くのは、問いや結論の一文だけ |
| どのスライドも「見出しと表」または「見出しと箇条書き」 | 主張からではなく、手元の材料から作成している | 主張ごとに証拠の示し方を選ぶ（`structure.md` の 3） |

## 2. 装飾についての考え方

スライドに置くのは、主張か証拠のどちらかに役立つ要素だけにする。迷ったら、その要素を削除すると聞き手が受け取る内容が減るかを考え、減らないなら削除する。

色は視線を集めるので、集める理由がある箇所にだけ使う。色には二つの役割がある。識別の色は対象ごとに固定し、強調の色は見てほしい箇所に使う。強調の色は 1 枚に 1 か所にする。色を使わない図も正当な選択である。

会場の後方から判別できるかで色を選ぶ。薄い灰色や、同じ色どうしの重なりは判別できない。識別の色は彩度を保つ。彩度を落とすと、視線を誘導できなくなる。小さい文字には強調の色を使わない。

余白は配置の一部であり、1 つの要素を動かすとほかの余白が変わる。1 か所だけを動かして終わりにせず、動かしたあとの全体を確認する。

## 3. 修正前後の例

### ツールの導入を紹介するデッキ（7 枚）

- 修正前: クリーム色の背景。見出しの上に小さな色つきのラベル。本文は角丸のカードの並び。コマンドは角丸の箱の中。文字は 12〜15 pt 相当。出典は薄い色。最後の 1 枚だけ濃い背景。見出しは「サーバーを一つ登録して、認証する」のような、動作の題目。
- 修正後: 白に近い背景。ラベルとカードをやめ、見出しを主張の一文にした（「alphaXiv MCP は mcp add コマンドで登録でき、Claude Code ではブラウザで、Codex では API キーで認証する」）。本文は 18 pt 相当以上。コマンドは箱なしの等幅フォント。色は 2 つのツールの名前に使った大きい太字と、その枠だけ。出典は左下で、ページ番号と同じ行。

### よく起きる崩れ

研究発表のスライドで実際に起きた例である。

補足を動かして、全体のバランスを崩した

- 修正前: 式と図のあるスライドで、式の中の記号についての注が、式から離れた右下にあった。注を右へ寄せると右端に飛び出し、戻すと右に空きができた。
- 修正後: このスライドで何を見せたいか（式と、その記号の関係）を決め直し、全体を配置し直した。
- 原因: 見せたいものを決めないまま、部品を 1 つずつ動かしていた。

指す線が、指す相手と同じ色だった

- 修正前: 青で塗った領域を、青い引き出し線で指していた。
- 修正後: 引き出し線をやめ、領域を濃い枠で囲み、ラベルの前に同じ塗りの小さな四角を置いた。
- 原因: 同じ色相の上に引いた同じ色の線は、後ろの席から見えない。

説明文が薄い灰色だった

- 修正前: 用語の説明を、小さい灰色の文字で添えていた。
- 修正後: 濃い文字で添え、用語と説明は位置と太さで区別した。
- 原因: 補足だから薄くすると考えると、読めなくなる。薄くするのは 1 段階だけにする。

コントラストの基準を満たすために、識別の色を暗くした

- 修正前: 識別の色で塗った文字がコントラストの基準に届かないので、色を暗くした。色がくすみ、色で見分ける役割を失った。
- 修正後: 識別の色で文字を塗るのは、大きい太字だけにした。小さい文字は本文の色にして、色見本（小さな四角）か位置で対象を示し、線や棒は元の色のままにした。
- 原因: 1 つの数値基準を、役割の違う文字すべてに適用していた。

箱を全面塗りつぶした

- 修正前: 2 つの箱を、濃い色で全面塗りつぶしていた。
- 修正後: 枠線と、ごく淡い同じ色の塗りにした。
- 原因: 塗りつぶしの上の文字は読みにくい。

並べた部品が、わずかにずれていた

- 修正前: 同じ種類の部品を 4 つ並べたうち、2 つがわずかにずれていた。
- 修正後: 位置を揃えた。
- 原因: 意図しないずれは、乱れか、意味のある差に見える。

実物の画像で、起きていないことを見せた

- 修正前: 先行研究が述べる一般的な危険を説明するために、手元の実データの画像を加工して「こうなる」と見せた。その実データでは、実際には起きない。
- 修正後: 一般論の模式図として描いた。描き方は同じ内容を扱った論文の図の慣例から選んだ。
- 原因: 図が示す内容を、元のデータで確認していなかった。

伝わらない図を、文字で補った

- 修正前: 抽象的な図に、説明の文字を追加していった。
- 修正後: 同じ内容を扱った文献の描き方を調べ、図そのものを作り直した。案を 2 つか 3 つ作って比べた。
- 原因: 文字を追加しても、図が示していない内容は伝わらない。

出典の書式がスライドごとに違った

- 修正前: 「手法名: 著者 (年), 会議名」「〜の論より: 手法名: 著者 (年)」「指標名: 著者 (年), ツール名」が混在していた。
- 修正後: 「手法名 (著者 et al., 年)」に統一し、会議名、役割を表す語、ツール名は書かないことにした。
- 原因: 1 枚ずつ書式を決めていた。最初に 1 つ決めて、全スライドに適用する。

自分の結果のスライドに、出典を追加した

- 修正前: 自分たちが測定した表のスライドに、比較相手の論文の出典を追加したため、脚注が下の要素とつながって見えた。
- 修正後: 出典を置かないことにした。
- 原因: 出典を置くのは、他人の主張や画像が出るスライドである。

自動の折り返しで、語の途中で改行された

- 修正前: ハイフンでつないだ固有の名前や、数の範囲（0–2）の途中で行が変わっていた。1 語だけが次の行に落ちて、下の要素と重なっている箇所もあった。
- 修正後: 文字は変えず、意味の切れ目で手動で改行した。
- 原因: 見出しとスライドの句の折り返しを、自動に任せていた。

## 4. 画像を確認するときの問い

検査スクリプトが測定するのは数値で測れる項目だけなので、配置のバランスと意味は、描画した画像で確認する。1 枚ずつと、全スライドを並べた一覧の両方で確認する。

1 枚ごと

- 最初に目が行く箇所は、このスライドの主張か、その証拠か。
- 見出しを隠しても、図から主張が読み取れるか。図を隠しても、見出しだけで主張が分かるか。
- 補足が主役より目立っていないか。
- 文字と図、文字と文字の間が詰まっていないか。反対に、片側だけに大きな空きができていないか。
- 色が付いている箇所は見てほしい箇所か。
- 行の終わり方は自然か。1 語だけの行、語の途中の改行はないか。
- 削除しても聞き手が受け取る内容が減らない要素はないか。

全スライドを並べて

- 見出しの位置、本文の開始位置、出典とページ番号の位置が揃っているか。
- 同じ対象が、全スライドで同じ色と同じ名前で出ているか。
- 同じ形式のスライドが続いていないか。続いているなら、主張が同じ種類だからか、手元の材料から作成したからか。
- 1 枚だけ雰囲気の違うスライドはないか。
- 前後のスライドで共通する要素が動いていないか。
